## 结论

**没有可以直接复用的实现**：生态里的"状态效果"几乎都是**节点 + delta 计时**（动作游戏路子），
而这一版要的是**回合制 + CSV 配置 + headless 可测的纯逻辑**。硬搬会把我们已经跑通、
且有 6000+ 条断言盯着的管线撬掉——**复制粘贴的成本比自研高**。

所以这一轮自研了两块（都在 `src/core/`，各约 100 行，配 `tests/test_buff.gd`）：

- `BuffService`：读 `buff_def`／`buff_stat`／`buff_grant`，给出极性、作用域、持续、叠加规则、
  数值修正与"谁在什么时机发哪个 buff"；
- `SetService`：`set_def`／`set_member`／`set_bonus` 的计数口径（只算已装备／已装配；
  装备套按件数、招式套按招数、**内功套按占格数之和**）与档位向下兼容。

## 借鉴（不算复用，记个出处）

- **三层划分**：把"属性值 / 修正项 / 效果"分开——GAIIS（MIT）就是这么分的，我们的
  `buff_def`（效果）＋`buff_stat`（修正）＋`AttributeCalculator` 贡献通道是同一个思路；
- **叠层各带计时**：GAIIS 给每层存一个剩余时间；我们的 08 设计是 `refresh`／`stack`／`unique`
  三种规则，等价但不逐层计时（回合制下更简单）；
- **把模板属性拷到实例**：hitzone（MIT）用 `get_property_list()` 拷贝 `@export` 字段——
  我们不需要（行实例本来就来自 CSV 构建期），但这条手法在别的场景可能有用。

## 复用落地：音频播放层（2026-10-03 深夜）

第五轮里"唯一对得上、但卡在素材"的那一个，这一轮**真的接上了**——照样没有引入第三方二进制：

| 复用什么 | 版本／许可 | 放在哪 | 怎么接 |
|---|---|---|---|
| `nathanhoad/godot_sound_manager` 的**运行时**：`sound_manager.gd`／`abstract_audio_player_pool.gd`／`sound_effects.gd`／`music.gd`／`ambient_sounds.gd`（含 `.uid`） | v2.6.2 / **MIT**（`addons/sound_manager/LICENSE` 原样保留） | `addons/sound_manager/` | **不用它的编辑器插件**：`src/audio/sfx.gd` 按需 `new()` 一个 manager 挂到场景树 root，`project.godot` 不加 autoload；总线布局用它带的 `default_bus_layout.tres`（`Sounds`／`Music` 两条）放到项目根 |

**没有跟着拿的东西**（逐条理由）：

- **编辑器插件**（`plugin.gd`／`plugin.cfg`）：它只干一件事——自动加 autoload。我们改成按需创建，
  就不需要它，也不动 `project.godot` 的 autoload 段。
- **示例音与示例场景**（`examples/`）：那是它的 demo 素材，与本作无关。
- **音乐／环境音**：只用 `play_sound` 这一条路；`music.gd`／`ambient_sounds.gd` 是 `sound_manager.gd`
  预加载的依赖，留着但不接（设计与表都没给音乐落点）。

音频文件**不是**从 GitHub 拉的：`tools/audio/make_placeholders.py` 用 Python 标准库 `wave` 合成 6 条占位音
（命中／暴击／胜利／败北／宝箱／火盆，合计约 100 KB），与 `tools/mapgen/make_placeholders.py` 是同一套
占位美术思路；音效侧到位后按**同名文件**替换即可，代码一行不用改。

集成时踩到的两个坑（代码里都留了注释，免得下一个人再踩）：

1. 播放层的 `_init` 会 `Engine.register_singleton("SoundManager", self)`，而**引擎单例是引擎持有的引用**——
   在 `--script`（自检）模式下退出会报 `12 ObjectDB instances were leaked`。修法：挂到 root 之后撤掉单例登记，
   节点生命周期交给场景树。
2. `--script` 模式下**没人回收挂在 root 上的节点**（这家仓库的用例都自己 `remove_child`＋`free`，原因就在这里）：
   把四条真实路径接上后实测泄漏涨到 **66** 个。修法：`Sfx.shutdown()` 由 `tools/run_tests.gd` 在所有用例跑完后调用。
   另外**不做静态资源缓存**——静态字段会在退出时留住 `AudioStream`（报 `N resources still in use`），
   而 `load()` 本来就命中引擎资源缓存。

## 第九轮（敌人属性模板统一）——1 命中，但用不了

设计 10 §二要把敌人模板从「派生数值列」换成与角色同一套**七维**（`attr_*` + `attr_to_stat`）。
按规矩搜了两组：`godot rpg stats attributes system`（**1 命中**）、
`godot enemy template data driven stats`（**0 命中**）。那唯一一条是
`G-Raffiti/core_attributes_system`：**0 星、无许可证、C# 写的**——三条都不对
（本项目是 GDScript-only，**没有许可证的代码不能复用**，这条与第五轮
`ChloePrime/Godot.RPG` 的结论同型）。也就是说这一块**没有可搬的通用件**：
「七维 → 派生数值」的映射本来就在本项目的 `attr_to_stat.csv` / `curve_def.csv` 里，
复用的对象应该是**我们自己的 `AttributeCalculator`**（那正是设计 10 §二说的「共用算法、分开存数据」）。
等设计与用户就表结构点头之后再动手（见 `框架说明.md` 决策 260 前后的登记）。
