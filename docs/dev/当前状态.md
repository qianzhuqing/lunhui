## 一、怎么验：一条命令

```bat
tools\run_all_checks.bat
```

末尾看到 `ALL CHECKS: PASSED` 即全绿（**步数以末尾 `passed steps` 为准**——这里不写死，
同下面「步数与耗时以输出为准」一条纪律；耗时看 `PERF total_elapsed_ms`，当前约 30 秒）。它依次跑：

| 步 | 验什么 |
|---|---|
| 单元自检 | 全部用例（含配置表构建与校验）；**用例数与断言条数以输出为准**——末尾那行 `SELFCHECK: OK (N assertions)`。这里故意不写死，同下面「步数与耗时以输出为准」一条纪律（写死的数字已经过期过一次） |
| 表校验 + 配表审计 | 51 张表 / 783 行；0 死列、0 没人用的常数；另按**设计措辞／可达性／钥匙道具／线索条数**列出一批**警告**（条数以运行输出为准，别在这里写死——写完就会过期）——那不是开发侧的待办，而是给策划的清单（哪件装备拿不到、哪部武学来源没实现…），**不挡验收**，补齐了它自己就消失 |
| 地图验收（07 §9） | 命名归属／连通性／可绕背袭／侧向通路／巡逻／性能 |
| 跨场景闭环 + 整局巡游 | **11 段真引擎**（段数=代码里的段标记，运行时会打印十几行 `LOOP` 证据——一段可能两行）：大地图→小地图、小地图→回大地图（不被立刻送回）、明雷战斗（**胜／败两种结局**）、驿站传送（去＋回）、房间战斗、副本巡游（开箱→完成度→可扫荡）、存档→读档指纹比对、主菜单新建→小镇（进店／打坐／手动存档读档／赌局位点）、隐藏 Boss 交接（酒葫芦→醉刀客→回图→记成 Boss）、**招募链**（读告示板 → 出图 → 回来在客栈入队 → 存档往返仍是 2 人）、**宝箱守卫**（荒村屠夫挡箱 → 文取给草药汤 → 开箱 → 旗标进档） |
| 11 个真实场景自检 | 引导（配置表诊断）／战斗／大地图／小地图／角色／商店／打坐／驿站／线索本／完成度／启动菜单；每页都打印 `LAYOUT`／`CONTENT`／`BACKDROP`／`COPY`（文案里不许出现表内 id 形态，决策 244） |
| 进程泄漏检查 | 跑完不许留下引擎进程（查不动也判失败） |

另外每一步跑完都会扫一遍自己的引擎日志：出现 `SCRIPT ERROR`（GDScript 运行期错误）就判红。
这类错误会**掐断命中的那个函数**——它后面的语句、以及调用方剩下的检查全都静默不跑，
而退出码与 `SELFCHECK: OK` 标记可能照样是绿的。2026-10-03 实测：主键索引越界曾让
排在后面的二十多张表的主键检查全部跳过（见 `框架说明.md` 决策 147／148）。

表校验里那几项「按设计文档表格排版解析」的比对（伤害类型／系别相克／职业方向／判定刻度）会打印
**覆盖率**（如 `比了 7/7 行`）：分子变小先去看文档表格是不是改了版式，**解析到 0 行直接报错**
——否则它会静默报成「0 处不一致」，和真比过一模一样（见 `框架说明.md` 决策 150）。

单跑某一块：`tools\run_tests.bat`（自检）、`tools\check_maps.bat`（地图验收）、
`tools\check_loop.bat`（跨场景闭环）、`tools\run_balance_analysis.bat`（平衡观测原始数据，
只读分析、不是门限，所以故意不接进上面那条总命令）。

另有两份**只读快照**（都不进验收）：`平衡观测.md`（数值打起来什么样）与
`性能观测.md`（4 人满装/40 条线索/30 层副本这些极端规模要多少毫秒）；
重跑分别是 `tools\run_balance_analysis.bat` 与 `tools\run_perf_analysis.bat`。

**带窗口的真实渲染冒烟**（headless 抓不到渲染路径的问题）2026-10-03 也跑过一轮：
**全部 11 个**场景自检在 **D3D12 Forward Mobile** 下都跑过（2026-10-03 从三个最重的扩到全量）、
日志无渲染报错；

（同样**不接进验收**——验收要能在无图形环境跑）。

| 驿站传送把回程落点记成驿站 | 从荒村出来会被拽回落雁坡 |
| 「自动战斗」按钮是假的 | 轮到我方就永远推不动（只有敌方回合会动） |
| 明雷「到期回原位」是死代码 | 倒计时写在被关掉的物理处理里 |
| 「宝箱全开」开不了门 | 条件把门后那箱也算进分母 + 奖励根本没发 |
| **败北后被同一队立刻再抓** | 推开距离不够（被墙顶回接触圈），没有接触宽限期 |
| **城镇的店没有名字** | 4 家店 + 3 个设施都是看不见的 Marker，玩家只能挨个按 E 试；现在有 `PlaceLabel_*` 店名标识（7 个） |
| **大地图的地标没有名字** | 图标画了、名字要开驿站在面板里才看得到；现在已揭开的 4 个地标图上直接写名字（未揭开不写，避免剧透） |
| **小地图的出口看不见** | 出口是看不见的坐标，而状态栏还让玩家「走 Exit 位点」；现在出口标了「出口」，没东西可交互时提示改成「按 Esc 回大地图」 |
| **副本里不知道自己在哪** | HUD 只有图名；现在写「第 N 层 房间名」（走一步就跟着刷新），城镇这种没有楼层的图不硬凑 |
| **软判定从来没掷过骰** | 设计 01 写着「soft 不足可掷骰，成功率 `0.5 + 差值 × 0.1`，夹 5%~95%」，代码却按「达标才过」跑，12 条判定里的 5 条 soft 全被当成硬门槛（低技能玩家在赌局／守夜这些点位上永远没机会）。现在 soft 真的掷骰、hard 不足就是做不到；顺带补上 `equip` 奖励（原来静默不发）与 `skillbook`／`boss` 的显式报错 |
| **赌局位点摆好了却没人接** | 地编在清风驿·客栈摆了 `Event_ev_gamble`，表里那行却只有 `region_id`——小地图只认 `scene_id`、大地图只在自家 **overworld** 里找位点，**两边都不收**，玩家站在客栈按 E 毫无反应；验收脚本还专门为它写了 `check_id != "ev_gamble"` 的写死例外。现在按「图上真的摆了位点」收，验收也改成硬校验（接不上就红），顺带发现塌陷山洞的碑文位点同样漏了 |
| **赌局赢的钱发成了背包物品** | 事件奖励直接 `add_item("item_money")`，于是「赢钱」给的是背包里一行可堆叠的「铜钱」，`inventory.money` 一文不涨——赢了买不了东西。现在「奖励物品入账」统一走 `BattleReward.grant_item()`：货币进钱、装备建实例、其余堆叠，与战斗／宝箱／扫荡同一口径 |
| **版式预算只量到面板外壳** | `get_combined_minimum_size()` 到 `ScrollContainer` 就断了：角色面板量到的 760 其实是 `_tabs.custom_minimum_size` 这个常量，4 人 + 长名字时成员行真实宽度 1218 也照样报 ok（横滚关着 = 内容被裁掉）。现在**七个面板**都再加一条内容宽度预算（`CONTENT`；角色面板还要逐页切 + 等一帧），见框架说明决策 100 |
| **败北结算没人验过** | `_settle()` 的败北分支一条断言都没有：次序写反、败北误发奖励、气血不留底，以前都不会红。现在真场景把全队按到 0 血跑一遍，零收获／回最近城镇＋气血回满＋清战斗外增益／照常存档全部钉住 |
| **改了槽位表，存档里的旧穿戴记录会偷偷加属性** | 戒指容量从 2 改成 1（或把 `ring` 整类删掉）后，界面只显示 1 枚，`contributions_for` 里**两枚都还在**——删掉槽位后那两枚连卸都卸不下来。现在「配表认不认得」只有 `_slot_capacities` 一处出处，装不下的记录读档时由 `reclaim_stranded_equipped` 退回背包；顺带钉住「实例序号不许复用」（丢了 `next_uid` 会静默覆盖背包物品） |
| **回购按全价扣钱、货只给一半** | 同一堆只剩 2 格空位、回购条目有 5 个时：扣 5 个的钱、只放进 2 个，另外 3 个连条目一起消失（买入路径早就写了「只按真正放进去的数量收钱」，回购漏了）。现在放不下就拒、放得下只按实际入包数量收钱，没买完的留在回购列表，界面写清「买回 ×2（背包放不下，剩下的还留在回购列表）」 |
| （开发侧事故，非玩家可见）**补丁把用例调用插进了它自己** | 给 `test_character_ui` 加调用点时上下文撞车，`_check_big_bag(db)` 被插进 `_check_big_bag` 自己的尾部 → 自己调自己、递归上千层，两个测试进程卡死。先被自检的「假绿」门限拦下（写了 102 处断言只跑了 86 条），查日志看到 1000 层调用帧；停掉卡死进程后改对。**审计这套机器连我自己也拦**（框架说明决策 104） |
| **平局被写成「败北」** | 胜负其实有四种（胜／败／撤／**平**），而结算只写了三分支：回合打满 50 判平局时掉进 else，卡片告诉玩家「败北」——玩家没输，这是假话；同一条结算里 `last_battle.winner` 却记着 `draw`。现在补上平局分支（零收获、明雷不清），用例钉住「写平局、不出现败北／胜利」 |
| **明雷重生在玩家脚下 → 当场开战** | 到期瞬间玩家正站在位点上（等着刷怪、或清完站着休息）时，明雷凭空出现、同一帧就触发遭遇，连看都没看见——和当年「败北后被同一队立刻再抓」同类。现在重生先「不武装」接触判定，玩家走出接触圈才恢复（与地图出口「先走出去一次」同一套做法） |
| **一大堆掉落把结算面板顶破** | 章节 Boss 多件掉落 + 带词条装备时，卡片那一行长成 109 字、换成 4 个视觉行，整页 663 > 648——底部按钮被挤出屏幕（和当年「711 > 648、标题被裁掉半行」同类）。现在卡片掉落行按「3 件 + 48 字」截断，写「…（共 N 件，明细见战报）」，完整清单进战报；`--battle-selftest` 加了「长文案」一档专门量它 |
| **背包满时开宝箱会说假话** | 宝箱摘要只看「拿到了什么」，不看「没捡起什么」——满包开箱时一个都没进去，摘要直接是空字符串，玩家看到「打开宝箱：」，以为箱子是空的。现在如实写「草药 ×3 没捡起（背包满）」，全没进去时写「背包放不下，什么都没捡起」 |
