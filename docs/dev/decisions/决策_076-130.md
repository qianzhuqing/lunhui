82. **AGENTS 里的三条硬约定以前只有「约定」，没有门限**（其中一条第一次跑就抓到真违规）。
    起因：连着几轮都在给「文档写了、代码没人管」的地方补机器（决策 71／80／81），于是回头看了一眼
    `AGENTS.md` 的硬约束清单，挑出三条**能机械验、坏了后果实在**的：

    ① **`src/` 不许直接读 `res://data/tables/`**——CSV 是构建期输入，运行期只读 `data/generated/*.tres`
       （直接读会绕过校验、导出后也可能不在包里）。白名单只有一处：`src/data/table_registry.gd` 的
       `TABLES_DIR`（**构建管线**就是靠它读 CSV 的，那是它该干的事），并且白名单自己也有「文件还在吗」的断言。
    ② **`tools/*.bat` 必须纯 ASCII + CRLF**——cmd 用本地代码页解析，非 ASCII 变乱码；LF-only 时
       `call :label` 的标签查找会失效。这条**第一次跑就抓到真违规**：`run_tests.bat` 一直是 LF-only
      （它没有标签所以侥幸能用）。已转成 CRLF，并单独跑了一次 `tools\run_tests.bat` 确认照样绿。
    ③ **`tools/*.ps1` 含非 ASCII 就必须带 UTF-8 BOM**——PowerShell 5.1 按 ANSI 读中文会连语法都报错。

    做法：`test_handshake` 加 `_check_repo_conventions()`（按**原始字节**读文件，`get_file_as_string`
    会先把编码理顺，验编码必须看字节），失败信息直接给字节位置（「第 9 字节是裸 LF」）。

    验证：**三条都做了反向验证**——② 是真实案例（改之前 1 条红：`tools/run_tests.bat 第 9 字节是裸 LF`，
    修好后绿）；① 往 `src/core/rng_service.gd` 临时加一行提到 `res://data/tables` → 红，恢复后哈希一致
    （`EC12B95E2563`）；③ 把 `tools/audit_table_usage.ps1` 的 BOM 剥掉 → 红，恢复后哈希一致（`E46C8EC614BA`）。

    把主场景改成 bootstrap 也会全绿，而玩家双击游戏就进了诊断场景。

83. **版式预算漏了「宽度」这一半**（`DESIGN_WIDTH` 声明了却从来没人量过）。
    起因：这轮想给界面加一条「控件不重叠」的门限，先去看现有版式预算怎么写的——结果发现
    `LayoutBudget` 里 `DESIGN_WIDTH := 1152` 摆在那儿，但 `fits()`／`ascii_line()` 只取
    `get_combined_minimum_size().y`。**横向膨胀**（多一列、按钮变长、敌人卡片加宽）会被屏幕右侧裁掉，
    而所有用例照样绿：高度那条当初就是为了「内容被屏幕底部裁掉、代码一声不吭」建的，宽度是同一个坑的另一半。

    （顺带说明为什么没做「控件不重叠」那条：这个工程的界面几乎全是容器排版（VBox/HBox/Scroll），
    容器在构造上就不会让子节点互相重叠——真正会重叠的只有跳字，而那是设计上就该盖在卡片上的。
    会出问题的是「塞不下被裁」，所以补宽度才是对症的那一刀。）

    做法：`LayoutBudget` 加 `min_width()`；`fits()` 改成**两个方向都量**（量不出来=失败，同一条纪律）；
    `ascii_line()` 打印 `LAYOUT min_width=W min_height=H limit=1152x648 ok=true`——所有面板都用这套共用函数，
    所以 8 个面板的 `--*-selftest` 一次性全部开始管宽度。

    先量了一遍现状（一次性探针）：主菜单 440／战斗 803／角色 792／商店 232／打坐 364／驿站 461／线索本 572／

107. **两组「刚好」边界：内力刚好够一招、架势正好被打空**（都是「差一点就翻脸」的 off-by-one）。
    ① 内力的判定写的是 `qi_cost > qi` 才拒，所以**刚好相等必须能用**——谁把它写成 `>=`，就变成
    「内力明明够却说不够」，而玩家省着内力用时最容易正好卡在这个数上。用例：
    `spend_qi(cost)` 在 `qi == cost` 时必须成功且归零、`qi == cost - 1` 时必须失败且不扣；
    `available_skills` 与体检表 `skill_options` 在「刚好够」时算可用、差一点时写明「内力不足」。
    ② 架势的 `take_poise_damage(poise)` 必须**刚好**进破绽（扣到 0、不出负数），差 1 点不能进；
    `reduce_poise_ratio`（背袭压低初始架势）有下限 1——比例拉满也不会一开场就破绽
    （设计只写「压低初始架势」，没写能压到 0）。

    验证：断言 5460 → **5479**（武学 95 → 105、架势与破绽 27 → 36）。
    **反向验证**：把 `spend_qi` 的 `<`、`available_skills`／`skill_options` 的 `>`
    三处一起改成边界错误的形式，再把 `take_poise_damage` 的 `<= 0` 改成 `< 0`、
    `reduce_poise_ratio` 的 `maxi(1, …)` 改成 `maxi(0, …)` → **11 条红**，
    含「内力刚好够：支付成功」「刚好够内力：这一招在可用列表里」「正好打空 → 进破绽」
    「背袭比例拉满也只压到 1（实际 0，期望 1）」；改回后全绿。

    ——断言立刻报「这一招要耗内力（实际 0，应大于 0）」，换成 `sk_xuanwei_02`（耗 8）才对。
    **边界样本要挑真的踩在边界上的那一行**，别凭名字挑。

108. **明雷到期那一瞬间玩家正站在位点上：以前会「凭空出现在脚下、同一帧就开战」**。

    验证：断言 5592 → **5600**（启动菜单用例 59 → 67）。**反向验证**：把 `load_game` 里

119. **回合末回复的三种边界**（溢出／减半后再封顶／死人）补成绊线。

121. **线索来源的解析口径没人直接验**——而它正是「每条隐藏至少两条线索」那道设计门限的底座。
    行类的 `clues()` 用 `split(";", false)` + `strip_edges()`（空段丢掉、每段去空白）。
    要是哪天改成 `split(";", true)`（保留空段），`"只有一条;"` 这种写法就会被机器数成两条而**假绿**——
    门限看着在守，实际守不住。做法：`test_clue._check_clue_source_parsing` 拿真实行 `duplicate(true)` 后改
    `clue_source`：`"  甲说的一句话  ;;;乙说的一句话;"` → 只解析出 2 条且首尾空白去掉；空字段 → 0 条；
    单条 → 1 条；`event_check` 那张表也走同一套解析。
    验证：断言 5613 → **5621**（线索本用例 69 → 77）。**反向验证**：把 `split(";", false)` 改成
    `split(";", true)` → 两条红，报出来的正是那副假绿样子：
    `空段丢掉：只剩两条（["甲说的一句话", "", "", "乙说的一句话", ""]）（实际 5，期望 2）`。

122. **卖出侧的另一半：一次卖光的形态**（以前只验过「卖 2 个剩 3 个」）。
    ① 卖得比手上多 → 被拒且数量不变；② **一次卖光** → 数量归 0、`has()` 为假、背包清单里不再有它

123. **奖励入账的「部分入包」数量口径**（`BattleReward.grant` 是掉落→资产的唯一口径）。

124. **背包满时开宝箱，界面会说假话**（真 bug，玩家可见）。`_drops_summary` 只看

128. **攻击招式写成 0 段：能用、却打不出任何伤害，还不报错**（新加一条构建期规则）。

129. **再补三条「静默无效」的数值门限**（决策 128 的同一类）。
