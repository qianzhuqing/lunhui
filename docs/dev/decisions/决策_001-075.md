1. **命中公式**：`clamp(命中基准 + 命中 − 闪避, 5%, 99%)`。玩家角色的命中基准是 1.0（敏给的 `hit_rate` 是加成），
   敌人是 0.0（`enemy_base.hit_rate` 本身就是命中率），见 `battle_actor.base_accuracy`。
2. **攻击力取值**：外功取 `atk_phys`，内功取 `atk_qi`，奇诡取两者均值。文档第 1 步的「技能基础值」在这里落为攻击力，
   第 2 步的「攻击属性系数」留给 buff 与被动（`modifiers.attack_stat_bonus`）。
3. **暴击倍率**为 `crit_base_mult + crit_dmg`（`crit_base_mult` 配在 `combat_const`，当前 1.5）；
   `enemy_base` 没有暴击伤害列，敌人统一取 +50%（`DamageResolver.DEFAULT_CRIT_DMG`）。
   九步管线的常量（`crit_base_mult`／`def_const`／`def_level_coeff`／`variance_min`／`variance_max`）全部从
   `combat_const.csv` 读，缺行才退回代码默认值并报错——**参数在表、公式在代码**。
   比率上限从 `stat_def.max_value` 读：穿透 0.75、格挡率 0.75、格挡减伤 0.8、减伤 0.6。
   位置纪律为「暴击与相克在防御之前、穿透在防御之前、格挡在防御之后、减伤在最后」；
   注意这些都是乘区，纯数值上可交换，**位置纪律靠 `detail` 里的中间值断言钉住**，不是靠最终伤害的差异
   （唯一数值可分辨的是穿透：它必须乘在防御值上而不是减免结果上，用例里有对照）。
4. **格挡与闪避互斥**：先判闪避（完全免伤、直接跳过后续），未闪避才判格挡（部分免伤）。
5. **槽位不写死**：`equip_base.slot` 与 `affix_pool.allow_slots` 都校验到 `equip_slot_def.slot_id`，
   武器槽还必须填 `weapon_type` 且落在该槽位的 `allow_weapon_types` 内；增删槽位只需改配表。
6. **敌人没有穿透与格挡**：`enemy_base` 没有这两列（设计待补），`EnemyFactory` 一律按 0 处理，
   玩家的穿透与格挡先在玩家侧生效；这条记在交接表的 `enemy_data` 备注里。
7. **递减曲线只吃 `cap` 与 `param`**（`eff = cap × attr / (attr + param)`），`rate` 仅作说明，与 `curve_def.csv` 的公式一致。
8. **`cap` 与 `stat_def.max_value` 为 0 视为无上限**（表里留空即 0）。
9. **保底计数键为 `drop_group|drop_row_id`**：文档写的是「每个 drop_group 独立计数」，但 `pity_count` 配在槽上，
   按槽计数更不含糊；计数带着走即可跨难度、跨周目继承（`PityTracker.to_dict/from_dict`）。
10. **运属性掉落机缘**取全队最高的 `drop_rate`，只放大非必掉槽，上限 25%（`attr_to_stat` 的保守方案）。
11. **敌人招式**暂由 `ai_template` 映射到 `skill_base`（`EnemyFactory.AI_SKILL_MAP`），等补 `enemy_skill.csv` 后改配表驱动。
12. **回合末回复**按 `hp_regen` / `qi_regen` 结算。
13. **回合上限 50**，打不完判平局，避免无解对局跑飞。
14. **武学表拆成三张**（0.6.0）：`skill_base` 只放身份与门槛，战斗数值在 `skill_active`、内功在 `skill_passive`，
   内功加成在 `skill_passive_stat`；校验器会查「active 一条明细、passive 一条明细、每部内功至少一条加成」。
15. **槽位上限走 `growth_const` 公式**（第二种「公式在代码、常数在表」的派生数值）：
   `招式槽 = 2 + floor(等级/5) + floor(悟性/8)`（上限 9）、`内功容量 = 2 + floor(等级/6) + floor(根骨/10)`（上限 7）。
   这两个数值不进 `attr_to_stat`，由 `GrowthCalculator` 算好后并入面板。
16. **槽位公式里的悟性／根骨取含装备的属性合计**（设计未注明「裸」；事件判定才明确要求裸属性）。
   若设计要改成裸值，只改 `GrowthCalculator.active_slots/passive_capacity` 的入参。
17. **熟练度倍率** = `1 + 熟练度 × 星级 mastery_gain`，乘在伤害管线第 1 步；
   熟练度 0~10（`growth_const.mastery_max`），成长来源未做，先由存档 `skill_mastery` 提供。
18. **敌人不受内力消耗限制**：`enemy_base` 没有内力列（`qi_max=0`），选招时只在「有内力池的单位」上检查消耗。
   这条与「敌人没有格挡／穿透列」一起记在交接表的 `enemy_data` 备注里，等设计补列。
19. **选招只挑管线支持的招式**：DoT 与反伤会被跳过（而不是每回合报错）；
   有武器类型标记的单位（玩家队伍）只能选到武器匹配或通用（`any`）的招式。
20. **架势与破绽**：命中时按 `skill_active.poise_damage + 攻击者 poise_break` 扣敌方架势，
   扣到 0 进入**破绽窗口（1 回合）**，窗口内受到伤害 +50%（`BattleSimulator.POISE_BREAK_DAMAGE_BONUS`），
   窗口结束架势重置、未破绽时每回合回复 `poise_max × 比例`（普通 10%、`ai_boss` 30%）。
   背袭会把敌方初始架势压到 70%（比例取 `combat_const.backstab_poise_reduce`）。
   两个数值表里还没有列，先写在代码里并回报设计：**玩家的架势池**（暂按 `40 + 8×等级`）与 **`poise_regen`**。
21. **界面骨架与版式预算**：战斗界面的骨架进 `scenes/battle_screen.tscn`，代码只做绑定（`_bind_ui()`），
    卡片行与跳字仍是运行时生成；整页最小高度必须 ≤ 设计分辨率（1152×648），
    由 `--battle-selftest` 断言。这条是**自动化能发现、肉眼对着代码看不出来**的那类问题
    （曾经 711 > 648：标题被裁掉半行，而代码没有任何报错）。
22. **武学门槛与槽位不含内功加成**：装内功 → 属性涨 → 容量涨 → 又能装一部，这条路会自我循环，
    「先装哪部内功」就变成了纯顺序问题，所以 `SkillLoadout.attrs()` 只取模板 + 加点 + 装备。
    内功加成只进派生数值（`CharacterSheet.contributions()`），不进门槛与槽位判定。
    面板显示的 `slot_active` / `passive_capacity` 也走同一份属性（`CharacterSheet.loadout_attrs()`），
    免得「面板显示 3 格、实际只让装 2 格」。这条不是空担心：`pf_xuanwei_05`（玄微心法·太清）
    就带 `attr:wu +5`，而悟性正是招式槽的入参，用例里钉了「跨过 /8 边界也不涨槽」。
    另外掉落学到的武学对**全队**生效（图鉴是收集口径，`collected_skill_count` 去重），
    单人专属来源（门派只传某一人、秘籍指定某人）未做，记在对接表 `skill_system` 备注里。
23. **武器 element 覆盖招式系别**：05 文档写「具体系别以每件装备自己的 `element` 为准」，
    所以 `PartyBuilder` 把身上武器的 element 放进 `tags.weapon_element`，
    `BattleSimulator._modifiers_for` 用它填 `element_override`（敌人没有装备，仍按招式自己的系别）。
    命中事件里的 `element` 字段就是这个最终系别——界面以后要按系别给跳字上色，读同一个字段就行。
    当前数据里没有「内功拳」的拳套（设计举例的乌木拳套还没进表），这条规则先由 `eq_sword_04`（奇诡剑）覆盖到。
24. **商店的两条补充口径**：**只收店里有 `sell_price` 的东西**（掉落装备没上架就不收，
    因为设计没给估价公式），**回购＝按卖出价撤销卖出**（上限 20 条，装备连词条一起回来）。
    另外医馆治疗的费用公式实现了，但**战斗外气血没有进存档**（队伍每次战斗按模板重建满血），
    所以治疗只能算价钱；这条与「消耗品使用缺效果数值列」一起等设计。
25. **异常的几率与强度公式**：04 文档只写了「运决定触发几率、智决定强度」，没给算式。这里落成
    `几率 = base_chance × status_chance_mul + debuff_chance`（夹 0~95%）、
    `每层伤害 × (1 + debuff_power)`，两个系数都由 `attr_to_stat` 从运／智换算出来（表驱动），
    敌方 `resistances` 作为 `(1 − 抗性)` 乘数读 `enemy_base` 的 `res_*` 列。加法对乘法、以及 95% 上限都是实现选择，等设计确认。
26. **首杀记录进存档**（v10 起 `GameState.first_kills`，键是 `drop_group`）：05 文档说首杀是「确定的惊喜」、
    重复刷是「随机的追求」，所以 `drop_table.csv` 里 `first_kill_only=1` 的槽只能领一次。以前这份记录只存在
    `GameSession` 会话里，退出重进就能再领一次（首个受害者是黑风寨 Boss 的黑风刀）——现在改由
    `GameState.mark_first_kill()` 落存档，战斗结算前调用，老档（v9 及更早）没有这份记录、一律当作「还没打过首杀」。
    扫荡（`DungeonService.sweep`）按设计不给首杀，固定传 `first_kill=false`。
27. **预兆与拆招**（04 文档的核心循环：「敌方出招前有一回合预兆，玩家可以花行动去拆招，读出后该招伤害减半并反涨自身架势」）：
    - **预兆**：每回合开始由 `BattleSimulator._refresh_intents()` 替每个活着的敌人定好这一回合的招式
      （`pick_skill` 同一套可用性判定）；`intent_of()` / `intent_lines()` 给界面用，敌人卡片上就是那一行「预兆：…」。
      敌人真正出手时走 `_skill_for()` **用预兆里那一招**——预兆了却临时变招，玩家就白拆了。
    - **拆招**：`parry(actor, target)` 花掉出手者这一次行动（和出招互斥），给目标打上 `_parried` 标记；
      那一招在 `_act_once` 里整招伤害 **×0.5**（设计原文「伤害减半」）。减半是乘在**现有增伤之后**再减半，
      免得「破绽增伤 +50%」和「拆招 −50%」在同一层互相抵消。
    - **反涨架势**：`+自身架势上限 × 15%`，夹在上限内。设计只写「反涨架势」没给数值，这个 15% 是开发侧定的，
      和 `poise_regen` 一样写成代码常量并记进交接表，等设计补表列；架势池为 0 的夹具不加（避免假日志）。
    - 一个敌人一回合只能被拆一次；不是我方行动、敌人已倒、没有预兆都会被 `parry_block_reason()` 拒绝并给出原因
      （界面上按钮直接置灰 + tooltip 写原因）。
28. **逃跑**（设计 02 只给了「被追击抓到 → 第一回合无法逃跑」，成功率公式没写，以下是开发侧定的口径）：
    - 触发：轮到我方行动时按「逃跑」，**花掉这一次行动**掷一次判定（和出招／拆招互斥）。
    - 成功率：`0.5 + 0.5 × (我方最高身法 − 敌方最高身法) / (我方最高身法 + 敌方最高身法)`，
      夹在 `25%~95%`。同身法 50%，身法高的一边更高；用「和」归一化是为了不引入量纲常数。
      三个常数（`FLEE_BASE_CHANCE` / `FLEE_MIN_CHANCE` / `FLEE_MAX_CHANCE`）写在 `BattleSimulator` 里，
      和 `poise_regen`、拆招架势一样**等设计补 `combat_const` 行**。
    - 成功：战斗以 `WINNER_FLEE` 收场——**不结算经验／铜钱／掉落**，**明雷不清**（还在原地，回来还能打），
      结算卡片写「撤退：脱离了战斗（没有经验与掉落）」。失败：白费一次行动，敌人照常出手。
    - 被追上（`Encounter.CONTACT_CAUGHT`）的第一回合由 `flee_block_reason()` 挡下并给出中文原因；
      界面按钮直接置灰 + tooltip 写原因，玩家不会按了才知道。
    - **回到大地图要把玩家推离明雷**（`OverworldController._push_player_out_of_contact()`）：
      没打赢（败北或撤退）时 `world_position` 就是接触点，也就是明雷身边；场景重建后明雷的接触闩归零，
      不推开就会被同一只明雷瞬间再抓一次。现在只在真的重叠时沿连线往外推（接触距离 + 30px）并提示「刚从遭遇里脱身」，
      正常落点不受影响。小地图不受这条影响（它的落点固定是入口房间）。
29. **占位阶段的表现三件**（设计 07 的「美术清单」里开发侧能先做的部分，美术到位后直接换贴图）：
    - **宝箱三档**（`chest.gd`）：按掉落组前缀解析 `copper` / `silver` / `gold`，给不同颜色、个头与名字
      （铜箱／银箱／金箱），开过之后统一换成暗色并写「已开」。解析规则 `resolve_tier()` 认不出就按铜箱。
    - **精英发光**（`roaming_enemy.gd`）：`is_elite` 的明雷挂一个八边形金色光晕（`EliteGlow`）＋呼吸明暗。
      地编的 `elite_marker`（`marker_elite_red`）贴图还没进项目，现在用程序化光晕顶着，表里的 id 不动，等美术换贴图。
      光晕**不能用 `z_index = -1`**（会被地面图层整个盖住，试过看不见），它是先 add 再 add 身体，靠兄弟顺序压在后面。
    - **出手／受击分帧**（`battle_screen.gd`）：出手是「蓄势压一下 → 探身弹出 → 收势回位」的缩放链，
      受击是「压扁 → 弹回」＋红光，破绽再多一段横抖。卡片挂在容器里，`position` 补间会被下一次排版顶掉，
      所以整段用 `scale`（容器不管缩放），绕中心缩放靠 `pivot_offset`。
30. **扫荡动画**（`dungeon_screen.gd`）：**掉落仍然在按下那一刻就结算**（逻辑不能等动画），
    动画只负责「看得见」——列表顶部冒出进度条、这一层的敌人房逐间打勾（`✓ 前院`），
    走完 0.6 秒再把结果落到状态栏并 `refresh()` 重算楼层列表。
    动画期间所有扫荡按钮置灰防连点，`press_sweep()` 会拒绝第二次调用。
    时间是自己数的（`step_sweep_animation(delta)`），不用 Tween——用例可以精确推帧，不靠真实帧率；
    进度条挂在滚动列表里而不是面板的 `Column` 末尾（面板竖向已经排满，塞末尾会被挤出屏幕，踩过）；
    动画结束**不要**手动把按钮一律打开，交给 `refresh()` 按各层进度重算（否则没通关的层会跟着变可扫，也踩过）。
31. **战斗外气血与医馆治疗**（存档 v11）：设计 05 写「治疗费用 = 缺失气血 × `service_price`」，
    而在此之前存档里根本没有「战斗外气血」——队伍每场战斗都按模板重建满血，医馆只能算价钱、按钮永远是灰的。
    - **表示法**：`GameState.char_hp`（char_id → 当前气血），**没有记录 = 满血**，所以新档与老档都不用特意填满值；
      `heal_all()` 就是清掉记录。`current_hp_of()` 返回 `-1` 表示「没有记录」（0 在游戏里是「倒下」，不能混）。
    - **写回**：战斗结算末尾 `battle_screen._write_back_hp()`，胜负与撤退都写，**下限 1 点**——
      倒下的角色回图留 1 点，免得全队 0 血把存档卡死。这条是开发侧定的（当时设计没定败北代价），已记进交接表等确认。**（0.8.1 起作废：败北改为「回最近到过的城镇＋气血回满＋清战斗外增益」——08 已定口径，见决策 213。）**
    - **进战斗**：`PartyBuilder.build_actor()` 按存档气血设 `actor.hp`（夹在 1~上限），所以「带伤进下一场」成立。
    - **医馆**：`ShopService.heal_preview()`（全队缺多少、要多少钱、每人当前气血）与 `heal_party()`（扣钱回满）。
      上限走 `PartyBuilder` 同一套「等级 + 加点 + 装备」，免得医馆按另一套算法算上限。
      界面上缺多少、要多少钱都写在治疗行里，钱不够时按钮置灰并写原因。
    - 面板：角色界面战斗属性段上面多一行「当前气血 x / y」（不满时提示可到医馆治疗）。
    - 顺手修掉一个**一直存在但没被断言发现**的面板排版 bug：五维行是「标签 + 加号」的 HBox，
      标签开了自动换行（`AUTOWRAP_WORD_SMART`）后最小宽度塌到一个字，HBox 就把它挤成竖排
      （截图里是「力 5（裸 5 ＋ 装备 0）」一个字一行）。给标签加 `SIZE_EXPAND_FILL` 就好，
      用例现在钉了 `AttrLabelstr.get_line_count() == 1`——这类「测试全绿但画面上是坏的」正是要断言兜住的。
32. **视觉自查揪出来的两处**（都是「断言只看节点在不在、看不出画面对不对」的那一类）：
    - **伤害跳字挂在浮层上**（`battle_screen._float_layer()`）：以前把跳字 `add_child` 到卡片里，
      VBoxContainer 每次排版都会把它的 `position` 按回卡片左边——数字跑到卡片外面、半个还被滚动区裁掉。
      现在跳字挂在铺满整屏的普通 Control（`FloatLayer`）上，位置由卡片 `global_position` 换算，谁也顶不掉它；
      浮动动画也因此真的动起来了。用例钉的是结构（父节点是 `FloatLayer`、不是卡片的子孙），
      真实位置由 `--battle-selftest` 与截图看。
    - **下架角色要在读档时清掉**（`GameState._prune_unknown_characters()`）：角色模板从早期的四个

    - **`press_return()` 之后原对象会被释放**：胜者／回合数要在切场景**之前**取出来（`.sim` 取晚了会报
      `previously freed`）。
    - **结论行必须 ASCII 打头**（`LOOP …` / `LOOPCHECK: OK`）：`findstr` 抓不到中文模式，这是项目老坑。
    - 战斗结局是随机的，所以断言按**结局分支**：赢了 → 明雷已清且落点=接触点；没赢 → 明雷不清且被推离接触圈。

    ```gdscript

        defeated = true
        respawn_left = float(respawn_seconds)
        visible = false
        set_physics_process(false)     # ← 问题在这
    func _physics_process(delta):
        if defeated:
            respawn_left -= delta      # ← 倒计时就在这个函数里
            if respawn_left <= 0.0: _respawn()
    ```

70. **平衡观测做成「可重跑的只读工具」，不进验收命令**（这一条是**方法**决策，不是 bug 修复）。
    起因：策划迟早要问「现在的数值打起来是什么样」，而这个问题只要有人手工跑一次、手抄一张表，
    下次改完表那张表就是**说过期的假话**——和「文档里的命令过期」是同一类坑（见决策 57）。
    做法：`tools\analysis_balance.gd` ＋ `tools\run_balance_analysis.bat`，一条命令打出
    胜率／平均回合／平均剩余气血／每队收益／升级门槛／单图明雷全清收益，结果整理进
    `docs/dev/平衡观测.md`（写明口径与快照日期，数值改了重跑再对比）。

    **为什么不接进 `run_all_checks.bat`**：
    - 它输出的是一张表，**没有「通过／不通过」**可判；要在里面设门限，只能断言「和上次的数字一样」，
      那策划每一次正常调数值都会变成假红——把噪声变成红灯，正是验收命令最该避免的（同 `PERF` 那条）；
    - 它在**单人默认队伍**（`character_base` 现在只有 1 行）下有意义，而补人到 3–4 人是已知待办，
      数字**预期会大改**，更不该钉死；
    - 它要 1400 场模拟、约 4 秒，塞给每次验收只是白花时间。

    验证：`tools\run_balance_analysis.bat` 跑通、退出码 0、输出六段表（本机 4.2 秒），
    报告里的胜率表与它逐格一致；顺带钉住一条**结构性**事实——70 个（等级×队伍）格子里
    「打不完」全是 0，即模拟器在任何数值下都能收敛（这条改数值也不该变）。

    **踩过的坑（写在这儿免得下次再犯）**：helper 的参数别写 `db: Resource`——
    `TableDb` 是 `RefCounted` 不是 `Resource`，注解写错会在 `_initialize()` 里当场报
    「不是 Resource 的子类」，而 `--script` 模式**不会因此退出**：错误抛出后回到主循环，
    控制台就那么挂着（当时是我手工 Ctrl+C 才结束的）。所以 `.bat` 里照样加了
    `--quit-after 900` 兜底（同 `check_scene.bat` 的理由），并且注释写明「跑挂了退出码仍可能是 0，
    要看输出」。这个脚本因此只用**无类型参数**，宁可少一层类型检查，也不要交一份空报告。
