依据：根 `AGENTS.md`「硬性约束」那条「单文件别长成上帝类」（2026-10-04 用户拍板，门限 **800 行**）。
「一个脚本只担一类职责」是目标；800 行是**能自动盯住的门限**，两者不冲突。

量法（行数变化后重跑这条刷新本表）：

```powershell
Get-ChildItem src,tests,tools -Recurse -Include *.gd |
  ForEach-Object { [pscustomobject]@{ Lines = (Get-Content -LiteralPath $_.FullName).Count;
                                       Path  = $_.FullName.Substring((Get-Location).Path.Length+1) } } |
  Where-Object { $_.Lines -gt 800 } | Sort-Object Lines -Descending
```

## 记一笔

- 门限 800 行是 2026-10-04 用户拍板的（起因：多处代码文件过大、出现上帝类）。
- 这是**活文档**：拆完一个划掉一个；行数变化后重跑上面那条命令刷新本表。
- **第一个拆完的：`tests/test_handshake.gd`（3843 → 基类 697 行 ＋ 八份族文件，最大 697）**。
   拆法（可照搬到下一批）：**只挪位置**——常量与共用夹具留基类、各族只放自己的检查、
   族文件直接放 `tests/` 平级（放进 `tests/handshake/` 子目录会让「孤儿用例」与「战斗用例种子」
   这两条**非递归**门限看不见它们，等于顺手削弱两道网）；八族各自是一份 suite，
   `run_tests` 的「静态断言点 vs 实际执行条数」按族照旧生效。
   两个必须知道的坑：① 原文里**顶层 `const` 夹在函数之间**（`TEST_ONLY_API_ALLOWED` 等 22 组，
   有的还是多行表），拆的时候要整条搬进基类，否则别的族会 `Identifier … not declared`；
   ② 逐个函数搬块时**别用管道取块**（管道把块数组拆成行，等于每行前插两行空行）。
- **门限怎么盯的（两向，2026-10-04 落地）**：`> 800 行` 的文件必须在本文件的「现状」表里有一行；
  反过来**登了表、文件却已经拆到 ≤ 800 行**也红（提醒把那行划掉，别让白名单越攒越大）；
  抬头那句「量：N 个超标」也必须等于实测的超标数。解析只认「现状」表的**第 2 列**——第 3 列
  （建议拆分轴）里也写着 `tests/handshake/*.gd` 这类**目标**路径，扫进来会变成"文件不存在"的假红；
  行数口径与上面那条命令一致（`Get-Content .Count`：**末尾换行不算一行**）。
