# 线程交接单

**用途**：一个 Codex 线程退休时，把「现在在哪、下一步做什么」写成文件，让接手的**新线程**读它继续，
而不是去读旧线程（旧线程的历史在墙根，读不了也读不动）。

**为什么要有这个目录**（2026-10-04）：四条线程同时到了每轮 65–90 万 token，
其中「小地编」直接 `systemError`。判据不是会话文件大小——
「小美术1」文件只有 2.0 MB，每轮却已经在发 65.7 万 token（图多的线程字节都压在 base64 里）。
量法见根 `AGENTS.md` 的「对话之间的协作约定」。

**写的人**：退休前那个线程（或替它收尾的人）。
**读的人**：新线程的第一件事就是读对应那一份。
**写法**：短。只写「在哪、下一步、开放问题、去哪找」，别把清单和内容搬进来——搬到文件里，这里只留路径。

**一个职能 ↔ 一个文件**：`docs/dev/交接/<职能>.md`（如 `小地编.md`）。
**别在这里再列一张表**——「谁在干这个活」（当前线程 id ＋ 对应交接单）
**唯一出处是根 `AGENTS.md` 的「当前执行者」表**；发消息前查它拿 id。

**主动退休的完整步骤**（触发线、五步顺序、为什么要先收尾再开新线程）同样在根 `AGENTS.md`
的「对话之间的协作约定 → 主动退休」那一节，别在这儿另抄一份。
