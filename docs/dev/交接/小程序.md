## ⚠️ 工具调用频率（这条线上最贵的坑，接手先看）

2026-10-04 实测这条线**某一轮 327 次工具调用 → 单轮 9,091 万 input token，占整条线程的 99%**。构成：

- 检索（`rg` / `Select-String`）**109 次（45%）**；
- 试探式读（`Get-Content … | Select-Object -Skip N -First M`）**64 次（26%）**——
  `test_overworld.gd` 被读了 **9 次**、`overworld_controller.gd` **8 次**、`local_map_controller.gd` **7 次**；
- **77% 的命令是单条**（242 次里 186 次没合并任何东西）。

**成本是「上下文 × 调用次数」——每调一次工具，整个上下文重发一遍。** 四条做法：

1. **一次读够**：`rg -n "^func |^const |^var "` 拿骨架 → **`rg -n -A 60 "^func _xxx"`** 把整个函数连上下文一次拿回；
   别一寸一寸挪（同文件读 6 次＝6 次重发）。
2. **合并命令**：读三个文件／看 git／量行数**串成一次调用**（`;` 分隔 ＋ 每段一句小标题）。
3. **合并检索**：`rg -n "甲|乙|丙"` 一次问全，别为一个关键词发一次。
4. **验收分档**：改一处→只跑最小的那条；**全量一轮最多一次**，放收尾。同文件多处改动合并进一个补丁。

**另外：同一时刻只许一条线程跑 `run_all_checks`**（并发会让「无残留引擎进程」误报、还会让两边同时重建
`data/generated`）。完整口径在 `tools/AGENTS.md` 的「工具调用纪律」与「同一时刻只许一条线程跑全量验收」。
