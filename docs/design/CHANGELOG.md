## [0.32.0] 2026-10-04

### UI 界面结构：12 屏示意图落地（交互与结构补充）

用户拿 `lunhui-ui-web.html`（水墨风 12 屏示意图）当 demo 验收通过，本轮把它的**交互细节**
落成两份待做清单：程序侧 `docs/dev/UI示意落地清单.md`、美术侧 `交接单_美术 §十`。
**结构上有四件事**：

1. **角色面板三页签各占一整屏**：属性／装备／武学仍是**同一个浮层**的三个页签，但不再挤在一屏里
   （用户原话「装备不用显示在一个界面，太挤了」）；顶部队伍页签可换人，底栏三个入口＝跳到对应页签。
2. **底部功能栏**：场景层常驻**七入口**（地图／行囊／武学／角色／纪事／系统／装备），
   与全局快捷键是同一组功能的两条路（键位给熟手、底栏给新手）。`14 §六` 已登记。
3. **游戏内「系统」浮层**：存档／读档**各自独立**＋战斗与显示开关＋音量——**待建**，`14 §二` 已登记为「待建」。
4. **悬停详情小卡**：物品／招式／内功／装备四类，0.2 秒浮出、元素上方、不挡点击——**待建**，是**部件**不是浮层。

**两处口径**：① 行囊分类标签按示意图取 **7 项**（`14 §四` 原写 4 项，下轮改）；
② **「纪事」＝线索本（`K`）扩成五类**：主线／支线／传闻／角色／隐藏；其中「传闻」按**听＋验**两态做，
来源只认现成的两处（随机事件的 `hint` 效果、观察点碎句），**不新开表**；副本完成度（`M`）仍是单独一屏。

**仍是「只做形态」的三处**：战斗记忆的语义、洗词条（Q6）、道具效果数值（Q33）——只摆开关与按钮，不接行为。

**落第 4 屏（角色详情）时对出来的五处口径（2026-10-04）**：

1. **槽位名照表**：七个装备槽以 `equip_slot_def` 的 `name_cn` 为准
   ——**武器／身体／腰带／肩部／下装／戒指／项链**（界面与交接单都不再自抄一套；id 不变）。
2. **战斗属性按 `stat_def` 逐行摆（28 行）**，不再按分组表摆 14 项：照表才看得到
   **毒抗／火抗／流血抗**（旧界面按分组表摆，正好把这三项漏了）。
3. **心性称号在「永久增益」下面**（按 `20 §四`／Q74①）——`UI示意落地清单 §二-4` 那一格原先写反了，已改。
4. **行囊分类＝6 档**：全部／消耗品／残页／材料／钥匙／装备；**「钥匙」按 `is_key_item` 判、不按 `item_type`**
   （`item_type=tool` 的铁镐因此归位，Q29 收口），**不做「兵器／护具」拆分**。
5. **新定三族图标的命名**（**都按行 id，不给表加列**，`15 §六` 已补）：七维 `icons/attr/<attr_id>.png`、
   派生数值 `icons/stat/<stat_id>.png`、空装备槽 `icons/slot/slot_<slot_id>.png`
   （**空槽单独一个目录**：`icons/equip/` 有硬门限「每张 png 都必须是 `equip_base` 的 id」，
   空槽不是装备，塞进去自检会红——`test_map_assets` 盯着）。

另外**「装备摘要」那一行不做「站位」**：前／后排规则还没定，没有数据可依（定了再加）。

### 大地图探索口径：只留城镇与驿站默认公开，其余都要自己走出来

用户原话：「大地图除了城镇等默认公开的地点，其他都需要额外探索才能知道入口，地图上才显示」。

**规则按类型判定，不逐行清点**（以后新加城镇／驿站自动公开，不会再漂）：

| 类别 | 谁 | 开局在地图上 |
|---|---|---|
| **默认公开** | `node_type=town`（清风驿）＋ `node_type=fast_travel`（驿站） | 一开局就亮着：地名 ＋ 图标 |
| **需探索** | 其余全部（`wild`／`dungeon`／`poi`） | **地图上完全不存在**——没有图标、没有地名、雾不擦，玩家只能走过去 |

揭开方式仍由 `map_region.unlock_condition` 表达（代码已整条按表驱动，`WorldMapService` 一行不用改）：
`proximity_N`（走到 N 格内）／`discover_<node_id>`（先发现那个地标）／持有类（`item_treasure_map`）。
**揭开之后**：地名常驻；图标按 16 §3.5 的类型规则给——**兴趣点不给图标**，
唯一例外是**藏宝图指向的石隙迷窟**（19 §5.6：玩家手里有图，图上有位置）。

**本轮具体改动**：

1. **落雁坡从「默认公开」改成 `proximity_5`**——它是主路第三站，但仍是野外，不是城镇。
   后果：**开局只亮清风驿与驿站两处**，主路要玩家自己走出来。
2. **兴趣点图标收口（待策划确认.md Q78 选 ①）**：塌陷山洞／荒村／废弃渡口三行 `icon` **清空**
   （靠地形认：山体上的洞口、焦黑屋舍群、水岸）；**石隙迷窟保留图标**（0.26 的藏宝图例外），
   并把值从 `icon_ruin` 改成 **`icon_shixi`**——这就是 **A8 的落地**，美术已出的
   `assets/sprites/icons/icon_shixi.png` 从此真的用上（以前大地图上显示的是荒村那道断墙）。
3. 顺手订正支路名单的一处漂移：废弃渡口那条是 **驿站 → 废弃渡口**（0.31.1 已定），
   `07 §3.2` 与 `交接单_地编 §四` 里的「清风驿→废弃渡口」按 16 §3.4 收口。

### 给地编的两条开放问题（结案）

1. **石隙细径要不要随藏宝图一起隐藏 —— 要。**
   `16 §3.2` 的分层表**加第 5 层 `Conditional`（条件地表）**：那 22 格碎石细径铺在这一层，
   程序按 `item_treasure_map` 整层显示／隐藏。`Ground／Decor／Overlay／Fog` 四层不动，
   `Overlay` 仍归路面／水面／桥。（`verify_maps` 与 `test_map_assets` 要认这一层。）
2. **死路「看得穿」选 ①「岩檐遮挡」。**
   岔缝内段压 `T_ROCK_EAVE` 到 **`Overlay`** 层，程序把 `Overlay` 在**玩家位于其下方时半透明化**
   ——这正是 07 §节点结构原文写的「玩家走到下面时半透明」，工程侧此前只做到「预留」。
   **不选 ②（岔缝拉到 ≥30 格）**：那段路本身枯燥，还要把石隙画布从 36×26 格撑大。
   两条都要程序动手，但**是两件事**（`Conditional` 显隐 ／ `Overlay` 半透明），可以一起排。

### UI 皮肤改「宣纸浅色」（0.32.0 内收口，不另升版本）

用户原话：「你做出来的代码完全没有符合策划的 UI 示意图」。根因是**两套皮肤并存**：
`15 §4.4` 原写**深色**（面板底 `#1E2224`、正文 `#D8D2C4`），而用户拿去当 demo 验收的
12 屏示意图是**宣纸浅色**；`UI示意落地清单` 开头又写着「冲突以 14／15 为准」，
所以程序一直照深色做。**这轮拍板：色值以示意图为准**（结构仍以 14 号为准）。

- **面板／浮层／窗口／底栏 ＝ 宣纸浅色**：面板底 `#F4ECD9 → #E6DBC0`、描边 `#A89A7E`、
  正文 `#322E26`、次要 `#5C554A`、禁用 `#8A8070`；
- **顶栏保持深墨**（`#211F1A → #16140F`，下边线 2px 朱红）——「面板别和地图抢视线」这条
  原意改由顶栏承担，不再是整块面板都深；
- **状态条三色与战斗浮字不动**（气血／架势／内力是信息色，不是皮肤色）；
- **美术侧多一条**：图标与立绘要加 **1px 墨色描边**，否则浅色图标落在宣纸上会化掉。

**改了两份文档**：`15 §4.4` 的色值表＋按钮四态表整段重写；`UI示意落地清单.md` 开头那句
读法补上「色值这一条 15 已按示意图改完，不再是冲突点」。

## [0.31.2] 2026-10-04

### 大地图扩容与表现（实机反馈六条）

用户试玩后对大地图提了六条：**①太小 ②洞穴之类要融进山体、别孤零零一个图标 ③区域之间要有距离
④不要那么多阻挡 ⑤点与点之间要有专门的路 ⑥要指路牌**。逐条落：

| 反馈 | 措施 |
|---|---|
| ① 太小 | 画布 **1024×768 → 2048×1536 px（32×24 → 64×48 格）**，**4 倍面积**；并且**相机默认 2× 放大**（一屏约 16×9 格）。这条正是 07 §十二 待确认第 8 条，**关闭** |
| ③ 区域间距 | 8 个节点坐标**重排**（`map_region.pos_x/pos_y` **本轮已改**）。主路四段间距 16–20 格（约 4–5 秒脚程） |
| ⑤ 专门的路 | 主路 1 条 ＋ 支路 4 条（名单见 16 §3.4），要求**连续可辨的路面、节点连着节点**——不是"空出一条通道" |
| ④ 障碍太多 | **主路及两侧保持开阔**；阻挡只在**区域边界**，且用"像墙其实是山／水"的自然边界；**禁止**在地图中央／路口／节点附近散布阻挡 |
| ② 融进山体 | **兴趣点 `icon` 留空**（16 §3.5 本来就该如此——数据与文档打架，本次按文档收口），靠**地形**认出来：山洞＝山体上的洞口、石隙＝岩缝、荒村＝焦黑屋舍群、渡口＝水岸。**山脉要成片、有厚度** |
| ⑥ 指路牌 | **新增**：主路节点附近各一块，木牌＋箭头；**文案进表**（`map_region` 加 `signpost_cn`）；**纯信息点**（不置旗标／不进完成度／不算判定） |

### 连带（要开发侧注意）

1. **代码耦合**：`overworld_controller._build_node_labels()` 用 `row.icon` 是否为空来决定"要不要画地名"。
   兴趣点清空图标后**名字也会消失** → 要**解耦**（名字只看"揭没揭开"）。
   这也解释了用户第一条反馈里"兴趣点没有名字"那一半。
2. **新列**：`map_region` 加 **`signpost_cn`**（`region_name_cn` 程序已加 ✓）。
3. **手感联动**：相机 2× 后移动观感变快，`WALK_SPEED`（180）**要重估**（11 §三）。
4. **`check_maps` 会红到地编重建大地图为止**——`map_region` 坐标已换，场景里的 Marker 与新坐标对不上。

### 修掉一个接口缺口：书生的「填充位」（**后果与修法都与原判不同**）

原判说"主角选了另外四位之一，队伍就凑不满 4 人"。**核实后：缺口成立，但后果更小、修法也不同。**

**三处已核的事实**：

1. **主角的 `char_id` 来自 `origin_id`**（`CreationService.build()` 传给 `new_game()`）——**选谁就是谁**；
2. `is_initial=1` **只作兜底**（`char_ids` 为空时才用）；
3. **`RecruitService._ready_rows()` 会跳过 `is_initial=1` 的行**——而 `scholar_fallen` 是唯一一行，
   所以**他永远不进「待加入」**。

**所以真缺口是「书生永远无法入队」，不是「凑不满 4 人」**：主角(1) ＋ 另外三位 ＝ **4**，正好凑满。

**原判的修法不可行**：`recruit_def` 的**主键就是 `char_id`**（`'recruit_def.csv' = 'char_id'`，
同一角色不能有两行），而校验器另写着「`is_initial=1` 的必须**恰好一条**」——
"加一行"撞主键，"改成 0 再加一行"会变成零条。

**最小修法：代码 2 行 ＋ 表 2 格**：

- `src/core/recruit_service.gd::_ready_rows()` 里的 `if int(row.is_initial) == 1: continue` **删掉**
  （下一句 `state.char_ids.has(...)` 已经管住重复：主角是书生时他在队里、照样跳过）；
- `recruit_def.scholar_fallen` 补 `join_condition=flag_board_read`／`join_scene=scene_qingfengyi`（**本轮已填**）。

**没有新增行、没有加列、没有动存档。**
