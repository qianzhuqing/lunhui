# 14 界面结构

本文只描述**结构与层级**，不写像素规格。版式的硬约束见第六节。

## 一、三层结构

界面按「谁能盖住谁」分三层，跨层关系必须固定，否则会出现
「商店开着的时候还能走路」这类问题。

| 层 | 内容 | 能否叠加 |
|---|---|---|
| **系统层** | 启动菜单、创建角色、设置 | 最高，盖住一切 |
| **浮层** | 角色／行囊／商店／打坐／驿站／线索本／完成度 | 盖在当前场景上，**可叠成栈**（见下） |

### 浮层是一个栈，不是一个状态

浮层之间**支持互相跳转**（在商店里按 Tab 直接开角色面板看装备），
所以「同时只开一个」这个模型不够用。改用**栈**：

| 操作 | 行为 |
|---|---|
| 打开某浮层 | 压栈 |
| 目标**已在栈里** | **弹回到它**，不重复压（防止 A→B→A→B 无限叠） |
| `Esc` | 弹一层；栈空则回到场景 |
| 栈深上限 | **3**；达上限再压则挤掉栈底（最早打开的那个） |

「目标已在栈里就弹回去」这条是关键——它让 A→B→A 变成「回到 A」而不是
「A 上面又压一个 A」，玩家不会越点越深。

**压栈时重新读一次状态**：从商店跳到角色面板，面板要反映穿上新装备后的属性，
不能复用上次打开时的快照。
| **场景层** | 大地图、小地图、战斗 | 一次只跑一个 |

**战斗是场景层**，不是浮层——进战斗时场景整个换掉，而不是盖一层。
所以战斗中按 Tab 开角色面板属于「浮层盖场景层」，与其他场景一致。

## 二、界面清单

| 界面 | 层 | 打开方式 | 主要作用 |
|---|---|---|---|
| 启动菜单 | 系统 | 游戏入口 | 新建／读档／退出／设置 |
| 创建角色 | 系统 | 启动菜单 → 新建 | 出身／天赋／七维（见 13 号文档） |
| 游戏内枢纽 | 场景 | 新建后进入 | 通往大地图、角色、行囊、退回菜单 |
| 大地图 | 场景 | 枢纽 → 进入大地图 | 探索、揭雾、驿站传送 |
| 小地图 | 场景 | 大地图 → 地标 | 房间战斗、宝箱、建筑交互 |
| 战斗 | 场景 | 撞敌／对话触发 | 六指令回合制 |
| 角色面板 | 浮层 | Tab／枢纽按钮 | 加点、穿脱装备、武学装配 |
| 行囊 | 浮层 | 枢纽按钮 | 物品与装备 |
| 商店 | 浮层 | 城镇建筑按 E | 买卖、治疗 |
| 打坐 | 浮层 | 客栈／门派按 E | 熟练度修炼 |
| 驿站 | 浮层 | 大地图驿站按 E | 传送、切难度 |
| 线索本 | 浮层 | 快捷键 | 已获得的线索 |
| 副本完成度 | 浮层 | 快捷键 | 宝箱／隐藏／事件的完成情况 |
| 系统（游戏内） | 浮层 | 底栏「系统」 | 存档／读档（**各自独立**）＋战斗与显示开关＋音量（**待建**） |

**本轮补三件**（示意图定的，逐条待做见 `docs/dev/UI示意落地清单.md`）：
① **游戏内「系统」浮层**（上表末行，代码还没建；启动菜单那套存读档照旧属系统层）；
② **悬停详情小卡**（物品／招式／内功／装备四类，0.2 秒浮出、不挡点击）——它是**部件**，不是浮层；
③ **底部功能栏**（七入口，见 §六「共同要求」）。三件都不改上面那三层结构。

**角色面板的三页签各占一整屏**（0.32.0，用户反馈）：属性／装备／武学仍是**同一个浮层**的三个页签，
但每一页自己铺满主体区，不把装备挤在属性页里；顶部队伍页签可换人，底栏三个入口＝跳到对应页签。

## 三、浮层的统一骨架

七个浮层共用同一套骨架，这样玩家学一次就够：

```
┌─ Backdrop（背板，半透明，盖住底下的场景）──────────┐
│  标题栏：界面名 ＋ 关闭提示                        │
│  标签页（可选）：角色面板用，其余不用              │
│  主体：滚动区（内容超出时滚动，不缩字号）          │
│  底部：说明行 ＋ 操作提示                          │
└────────────────────────────────────────────────────┘
```

**背板是硬要求。** 浮层是按 E／Tab 直接盖在当前场景上的，底下是地图和 NPC，
不铺背板字会被糊掉。单独打开看不出来（背后是空窗口），只有叠在场景上才暴露。

## 四、七个浮层的逐界面结构

第三节只给了统一骨架。**每个浮层里装什么**在这里定，
否则美术不知道要画几张卡片、程序不知道要留几行。

| 浮层 | 主体内容 | 底部提示 |
|---|---|---|
| **角色面板** | 左侧立绘（320×480）｜右侧标签页：属性／装备／武学｜属性页含七维条形图与派生数值 | Tab 切换页签，Esc 返回 |
| **行囊** | 分类标签（材料／消耗品／装备／钥匙）＋ 列表 ＋ 详情 | 装备可穿脱 |
| **商店** | 左：货架列表（名／价／剩余）；右：玩家背包可卖列表；顶部：持有铜钱 | Enter 买／卖，Esc 返回 |
| **打坐** | 已装武学列表 ＋ 每部的熟练度条与打坐费用 ＋ 剩余铜钱 | Enter 修炼，可连续 |
| **驿站** | 已揭开地标列表 ＋ 难度切换 | Enter 传送／切难度 |
| **线索本** | 已获得的线索列表（来源 ＋ 文本），按章节分组 | 滚轮翻阅 |
| **副本完成度** | 四项完成度（宝箱／隐藏房间／隐藏 Boss／事件）＋ 可扫荡层 | Enter 扫荡 |
| **NPC 信息** | **头像（64×64）**／名字／称号／所属／等级／**好感度条形**／一句「人味」介绍 | Esc 返回 |

### NPC 信息面板的结构

```
┌─ 王铁 ────────────────────────┐
│ ┌────┐ 清风驿铁匠      Lv.5   │
│ │头像│ 好感度 ████░░░░░░  35  │
│ └────┘                        │
│ 清风驿的老铁匠，打了三十年铁。│
│ 据说年轻时在镖局走过镖，      │
│ 手上有一道刀疤。              │
│                               │
│ Esc 返回                      │
└───────────────────────────────┘
```

**头像规格 64×64**（原生 32×32 放大 2×），与 UI 的整数倍缩放一致；
美术要求见 15 号 §4.2。

**头像放在左上角**，与名字、称号、等级、好感度同排——
这几项是"这人是谁"的一组信息，**不要拆到两处**。

### 三条共性要求

**零、NPC 信息与交互菜单是两件事。** 按一个键**只看信息**，
按另一个键才进交互（赠送／切磋／偷窃／兑换／任务）。
合在一起会让「我只是想看看这人是谁」变成一次有风险的操作。

**所有 NPC 都能看信息**，信息文案来自 `npc_def.info_text_cn`，
**必须显示好感度与条形**——玩家要判断「还差多少能换东西」。

**一、每个浮层的顶部都要有「剩余配额」**——角色面板显示剩余属性点与天赋点，
打坐显示剩余铜钱，商店显示持有铜钱。**玩家不该为了看一个数字而关掉界面。**

**二、列表类浮层要能滚动，且滚动条可见。** 武学 59 部、装备 24 件，
列表一定超出屏幕。**内容超出时滚动，不缩字号**（第七节的纪律）。

**三、所有浮层的关闭提示统一写 `Esc`。** 栈管理之后 `Esc` 是唯一的返回键，
不要在某个界面里变成"关闭全部"。

战斗是信息量最大的一个，单独定结构。

```
┌───────────────────────────────────────────────┐
│ 顶部：敌我态势（双方单位：名字／气血／架势）    │
├──────────────────────┬────────────────────────┤
│ 左侧：我方单位详情    │ 右侧：增益减益面板      │
│  · 气血／内力／架势   │  · 减益（红）在上       │
│  · 武器与已装内功     │  · 增益（蓝）在下       │
│                       │  · 每个显示剩余回合／层数│
├──────────────────────┴────────────────────────┤
│ 中部：敌方预兆（这一回合敌人打算用什么招）      │
├───────────────────────────────────────────────┤
│ 底部：六指令行                                 │
│  普通攻击 │ 招式 │ 内功 │ 道具 │ 主动防御 │ 逃跑 │
├───────────────────────────────────────────────┤
│ 日志：最近的战斗信息（可滚动）                  │
└───────────────────────────────────────────────┘
```

### 三条要点

**一、预兆必须显眼。** 设计 04 的核心循环是「看预兆 → 决定拆招还是硬吃」，
预兆藏在角落等于这套机制没做。它要占一整条横带。

**二、增益减益面板是常驻的，不是弹窗。** 玩家要随时能看见自己还剩几回合的状态；
做成需要按键才看的东西，等于逼玩家每回合多按一次。

**面板的排序是「减益在前」**（0.28.0 定，与 08 号文档一致）：第一屏要回答的是
「我现在有什么危险」，不是「我有什么好处」；同类按剩余回合升序。
**固定顺序、不按获得时间跳动**——会跳的列表玩家读不出变化。

**三、六指令行是唯一入口。** 招式与内功都从这一行进去选，不散落在别处。
`内功` 进去是「催动已装内功」，不是查看被动——被动在角色面板看。

## 六、场景层 HUD

### 大地图

| 元素 | 位置 | 规则 |
|---|---|---|
| 地名 | 每个已揭开地标旁 | **常驻显示**，不依赖悬停（见 11 号文档） |
| **大区名** | **HUD 左上角** | **常驻一行**（本章是「江南道·东部」）；与地标名两级，见 11 号 §三 |
| 当前目标 | 左上角 | 一行，来自 `guide_step` |
| 战斗外增益 | 目标下方 | 显示剩余时间，进战斗后转整场 |
| **随机事件提示** | 目标下方（与增益同区） | 一行模糊提示（「远处有车马声」）；**同一时刻最多一条**，多个事件取最近的 |
| **队伍状态栏** | 屏幕一侧（贴边竖排） | 四行：头像／名字／等级／气血条／内力条；**空位写「空位」**，不摆 0 长度的条 |
| **底部功能栏** | **屏幕底部** | **常驻七入口**：地图／行囊／武学／角色／纪事／系统／装备；当前所在高亮。浮层的入口是「浮层 ＋ 页签」的二元组 |
| 角落小地图 | 屏幕右下 | **待定**（自身／明雷／出口三类点）——还没拍板要不要，先不摆 |

### 小地图

| 元素 | 规则 |
|---|---|
| 建筑名 | **常驻**（铁匠铺、木桩、客栈…） |
| 房间名 | **常驻**（左上角，进入哪个房间就显示哪个） |
| 当前目标 | 同大地图 |

### 共同要求

**地名与建筑名常驻**是 11 号文档定的口径，玩家找不到校场就是因为它没实现。

**底部功能栏**在场景层常驻（大地图与小地图同一套），它与 §八 的全局快捷键是**同一组功能的两条路**：
键位给熟手、底栏给新手，两边都得留。

## 七、三条 UI 纪律（有门限盯着）

### 一、版式预算：整页 ≤ 1152×648，两个方向都要过

不只量高度。横向膨胀会被屏幕右侧裁掉，而代码一声不吭。
量法要量到**滚动区里的内容**，不能只量面板外壳——外壳的最小尺寸
会在滚动容器处截断，量到的其实是个常量。

**当前余量最紧的是战斗界面**：技能行按上限撑满时离 648 只剩十几像素。
往战斗界面加行之前先想清楚从哪儿腾。

### 二、界面文字不许出现表内 id

`eq_sword_01`、`chapter_01` 这种形态一律不许出现在控件文字里，
要用表里的 `name_cn`。玩家不该看到 id。

### 三、内容超出时滚动，不缩字号

缩字号会让「量不出来」和「塞得下」变成同一件事——
版式预算就失去意义了。

## 八、输入约定

| 操作 | 说明 |
|---|---|
| 移动 | 方向键／WASD |
| 交互 | **E**（建筑、位点；对 NPC 是进入交互菜单） |
| 看 NPC 信息 | **Q**（只读面板，无副作用；见 19 号第三节） |
| 开角色面板 | Tab |
| 开线索本／完成度 | 快捷键 |
| 关闭浮层 | Esc |
| 战斗指令 | 方向键选择 ＋ 确认键 |

**键位只在 `input_setup.gd` 一处注册**，不要散落到各个场景。

## 已定口径（2026-10-04）

**浮层支持互相跳转**，用栈管理，「关闭后回到哪」由弹栈规则解决（见第一节）。

**小地图房间名常驻**，与地名、建筑名同一口径——
玩家的位置感不该靠记忆或悬停来维持。

### 全局快捷键

既然浮层可以互跳，常用面板的快捷键就该**在任何浮层里都可用**，
而不是只在枢纽页生效：

| 键 | 打开 |
|---|---|
| `Tab` | 角色面板 |
| `I` | 行囊 |
| `K` | 线索本 |
| `M` | 副本完成度 |
| `Esc` | 弹一层 |

这样不必为「商店 → 角色」这类组合单独做入口按钮：
玩家在任何地方按 `Tab` 都能看角色，`Esc` 退回原处。
