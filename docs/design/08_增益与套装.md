# 08 增益与套装

## 统一模型：一切增益减益都是 buff

**不再有「特殊效果」「被动效果」「套装效果」「运功效果」这些各写各的概念。**
它们全部收敛成一个东西：**buff**。

| 原来的说法 | 现在 |
|---|---|
| 装备的 `special_effect` | 装备触发的 buff |
| 内功的 `passive_effect` | 内功的常驻 buff 或运功 buff |
| 套装第 N 件的效果 | 套装达到 N 件时发的一个 buff |
| 招式的增益效果 | 招式命中/施放时发的 buff |
| 异常状态（中毒、灼伤…） | 减益 buff（DoT 明细仍走 `status_effect`） |

好处只有一个但很重要：**玩家只需要理解一套规则**，开发只需要一套结算。

## buff 的四个维度

每个 buff 由四个维度定义，配置见 `buff_def.csv`。

### 一、极性

`is_debuff`：0 增益 / 1 减益。**增益与减益走同一套机制**，只是极性不同，
UI 上分红蓝两色。

### 二、作用域

| scope | 名称 | 战斗外 | 进战斗后 |
|---|---|---|---|
| `battle` | 战斗内增益 | 不存在 | 按回合递减，战斗结束清除 |
| `field` | 战斗外增益 | **按现实时间计时**，到点失效 | **维持整场战斗**，不递减 |

**战斗外增益有两段生命：**

1. **战斗外**：有时长，按现实时间走（打坐余韵 10 分钟、饱食 5 分钟）。
   这段时长就是它的有效期，过期即消失。
2. **进战斗后**：不再按回合递减，**维持整场战斗**，战斗结束才消失。

好处是玩家进战斗前不用算「我这个状态还剩几回合够不够打完」——
战斗外有时长的紧迫感，战斗内则不用操心。

**两种 scope 的计数字段不同，配表时别看错：**

| scope | 用哪个字段 | 单位 |
|---|---|---|
| `battle` | `duration` | 回合（`0` 常驻 / `-1` 整场） |
| `field` | `field_minutes` | 分钟 |

### 三、持续

| duration | 含义 |
|---|---|
| `> 0` | 剩余回合数，每回合末 −1，归零即失效 |
| `0` | **常驻**：随来源存在而存在（卸下装备／换下内功即失效） |
| `-1` | 持续到本场战斗结束 |

套装与被动内功的数值加成用 `0`（常驻），主动催动与触发的用正数。

### 四、叠加

| stack_rule | 规则 | 典型用途 |
|---|---|---|
| `refresh` | 同源同 buff 只刷新剩余回合，不叠层 | 多数增益 |
| `stack` | 叠层，层数上限 `max_stack` | DoT、破防 |
| `unique` | 全局唯一，重复获得无效 | 套装、姿态类 |

**不同来源的同一 buff 各自独立计时**，只有 `unique` 例外。

## 与 status_effect 的分工

`status_effect.csv` 是**持续伤害类减益的专用明细表**（每层伤害、结算时机、快照规则），
它保持不动；`buff_def.csv` 管其余所有增益减益。

边界一句话：**会逐回合掉血的走 `status_effect`，其余走 `buff_def`。**

UI 面板把两者**合并成一条列表**展示，玩家看不出这是两套表——
这是刻意的：对内是两张表，对外是一个概念。

> 已知不优雅：确实是同一概念的两张表。要合并需要把 `status_effect` 并进 `buff_def`
> 并改 `BattleActor`，动的是已经跑通的异常状态系统。**本轮不做**，
> 等 buff 系统稳定后再评估合并。

## 战斗指令

战斗界面固定六条指令，是**唯一的行动入口**：

| 指令 | 内容 | 消耗 |
|---|---|---|
| 普通攻击 | 不耗内力，固定倍率，可触发武器特效 | 一次行动 |
| 招式 | 打开招式列表选一招施放 | 一次行动＋内力 |
| 内功 | 催动已装内功，获得其运功 buff | 一次行动＋内力 |
| 道具 | 使用 `use_context=battle` 的道具 | 一次行动 |
| 主动防御 | 本回合进入防御姿态 | 一次行动 |
| 逃跑 | 掷一次逃跑判定 | 一次行动 |

### 内功从「纯被动」变成「可主动催动」

这是本轮最大的机制变化。每部内功现在有**两种生效方式**：

| 方式 | 效果 | 何时生效 |
|---|---|---|
| 装备即生效 | `skill_passive_stat` 里的属性与派生数值加成 | 常驻 |
| 主动催动 | 一个运功 buff（`buff_grant` 里 `trigger=on_cast`） | 花一次行动催动 |

被动数值保证「装上就有用」，运功 buff 提供「关键时刻能爆发」。
这样内功指令才有存在意义，而不是一个只列被动说明的面板。

### 主动防御

一次行动换一个**防御姿态 buff**：本回合减伤、架势回复，且**下回合先手**。

与既有的「拆招」不同：拆招是**针对敌人预兆那一招**的精确应对，
主动防御是**不挑招的通用减伤**。前者要求读招，后者无脑但收益低。

## 战败处理

战斗失败（含被追击抓到后的失败）后：

1. **全队回到最近到过的出生点或城镇**（清风驿／驿站，取最近的一个）
2. **全队气血回满**——回城与回血是两件事，同时做，不冲突
3. 不扣铜钱、不掉装备（第一章不做死亡惩罚）
4. 战斗外增益全部清除

**平局（回合打满）不按战败处理**：零收获，留在原地。


## 套装效果

装备、招式、内功都支持套装，共用一套规则。

### 定义

| 表 | 作用 |
|---|---|
| `set_def.csv` | 套装本体：id、名称、类别 |
| `set_member.csv` | 套装包含哪些成员 |
| `set_bonus.csv` | 达到几件时发哪个 buff |

`set_kind` 三类：

| set_kind | 成员是什么 | 计数口径 |
|---|---|---|
| `equip` | 装备 id | 当前**穿在身上**的件数 |
| `skill_active` | 招式 id | 当前**装配**的招式数 |
| `skill_passive` | 内功 id | 当前**装配**的内功数 |

### 关键规则

**只算已装备／已装配的成员**，背包里和已学会但没装的不算。
这条很重要：否则玩家会为了凑套装把不用的东西全带上。

**同一套装的档位向下兼容**：达到 4 件时，2 件档的 buff 也生效。
所以 `set_bonus` 的每一档是**独立叠加**的，不是替换。

**每档发的也是一个 buff**，所以套装的减益、控制、DoT 全部能用同一套机制表达，
不需要为「套装」单开一套结算。

### 第一章的套装规模

第一章只做 **3 套**，作为机制的验证：

| 套装 | 类别 | 成员数 | 档位 |
|---|---|---|---|
| 黑风寨 | equip | 4 | 2 件 / 4 件 |
| 玄微剑意 | skill_active | 5 | 3 招 / 5 招 |
| 玄微心法 | skill_passive | 5 | **4 格 / 7 格**（以 `set_bonus` 现表为准，2026-10-04 订正；本表原先写「3 格 / 5 格」是错的） |

装备套用「件数」，招式套用「招数」，内功套用**占格数之和**——
因为内功已经是占格制，用格数比用部数更符合它自己的度量。

## UI 呈现要求

### 增益减益面板

战斗界面必须有一块**常驻区域**显示当前所有 buff 与 debuff：

| 要求 | 说明 |
|---|---|
| 合并显示 | `status_effect` 与 `buff_def` 合成一条列表，玩家看不出两套表 |
| 极性区分 | 增益蓝、减益红，色盲可辨（配图标形状） |
| 显示剩余回合 | 每个 buff 右上角标剩余回合数；常驻显示 ∞ |
| 显示层数 | 可叠层的显示 ×N |
| 悬浮说明 | 鼠标悬停／手柄选中时显示名称与效果 |

### 战斗外也要能看到

大地图与城镇的 HUD 上，**战斗外增益**必须可见——
否则玩家不知道自己带着一个还剩 2 回合的状态走进战斗。

### 排序

固定顺序，不要按获得时间跳动：**减益在前**（玩家更需要看到危机），
同类按剩余回合升序（快过期的在前）。

## 配置表

| 表 | 用途 |
|---|---|
| `buff_def.csv` | buff 本体：极性、作用域、持续、叠加规则 |
| `buff_stat.csv` | buff 的属性与派生数值修正 |
| `buff_grant.csv` | 来源 → buff：谁在什么时机发哪个 buff |
| `set_def.csv` | 套装本体 |
| `set_member.csv` | 套装成员 |
| `set_bonus.csv` | 套装的件数档位 → buff |

**全部是新增表，不改任何既有 CSV 的列。** 这样对已经跑通的系统零破坏，
开发侧只需要登记新表。

## 参数口径（2026-10-04 拍板，Q83–Q89）

开发侧把 buff 系统的参数缺口一次开成七条（`docs/dev/待策划确认.md` §三 Q83–Q89）。
**下面就是答案，只给数**；列名与代码通道由开发侧定。

| 条 | 结论 |
|---|---|
| **Q83 套装数值以哪份为准** | **以 `set_bonus` 现表为准**：黑风 2 件（力 +3）／4 件（破架势 +8、力 +4）；玄微剑 3 招（敏 +3）／5 招（暴击率 +6%、穿透率 +6%）；玄微心法 4 格（内力上限 +40）／7 格（内力回复 +2、内伤抗性 +10%）。**12 屏示意图那张套装卡只当演示、不作数**（它是我为说明信息层级画的），除 Q84 那一条单独采纳。 |
| **Q84 招式段数 +1** | **做**，措辞统一成「**段数 +1**」（「起手后追打」是同一件事的散文说法）。`stat_def` 加派生值 **`extra_hit`**（整数，**上限 2**）；结算 `段数 = skill_active.hit_count + extra_hit`；**只对「招式」指令生效，普通攻击不吃**（否则套装白送普攻流一条）。第一章只给一处数：**玄微剑 3 招档**那条 buff 加一行 `stat:extra_hit = 1`（与「敏 +3」并存）。**2026-10-13 加第二条来源**：**内功满级（熟练 10）→ `extra_hit +1`**（**只有太清 `pf_xuanwei_05` 一部**，见 `08 §内功满级签名`），上限 2 不变。 |
| **Q85 四个战斗常数** | 数值**照现状确认**：主动防御＝本回合减伤 25%、外防 +15、回复自身架势上限 15%；拆招＝那一招伤害 ×0.5、拆招者架势 +上限 15%；逃跑＝`0.5 + 0.5×(身法差／身法和)`、夹 25%~95%；破绽窗口＝伤害 +50%。**赞成补进 `combat_const` 查表**——这几个数会随平衡动，写死在代码里等于每次调平衡都要改代码。 |
| **Q86 灼伤削防／内伤回气** | **补两列**：`status_effect.burn_def_cut` ＝ **0.05**（每层削 5% 外功防御）、`status_effect.qi_regen_mul` ＝ **0.5**（内力回复减半）；其余行填默认值（0／1）。 |
| **Q87 内功催动耗气** | `skill_passive` 加 `qi_cost`，**按占格 ×6 填**：1 格 **6**／2 格 **12**／3 格 **18**。依据：运功的收益是「该内功常驻加成临时翻倍」，占格越大翻得越多，所以按占格线性；量级与招式（6~14 气）同档。 |
| **Q88 反伤／流血换位** | **两条本章都不做**。① 反伤：规则照 `damage_type.dmg_reflect`（直伤、不吃防御、不可闪避）——受击后按**所受伤的 10%** 回敬、**每回合最多 1 次**、**反伤不再触发反伤**；但**第一章没有任何一行发 `dmg_reflect`**，通道做出来也永远不会触发，等第二章有来源（装备／内功）再做。② 流血换位：**它依赖前／后排站位，而站位规则还没定**（代码里那条「有意不钉」正是它）——站位定了再开，本章从清单划掉。 |
| **Q89 `buff_grant` 来源组合** | ① **放开 `item` ＋ `on_consume`**（丹药／酒给自己上 buff；具体数值随 Q33「道具效果数值列」一起给）；② **不放开 `event`**（本章没有一行要用，放开只是多一条没人走的路）；③ 现有 `equip`／`set`／`skill_active`／`skill_passive` 四种够用。 |

## 内功满级签名（熟练 10，2026-10-13 拍板）

**用户口径**：内功**熟练满级**后给一条**特殊效果**，**适用于所有招式**，而且是**装上才生效**——
「不是单纯加数值，要能改变招式的玩法」。**段数 +1 只是其中一部高级内功（太清）的满级效果**，不是通用奖励。

四条规则：

1. **门槛＝满级（熟练 10，`growth_const.mastery_max`）**，不是某个中途档位——练满才算（从 1 练到 10 的打坐费 ≈ **113× 基础**，
   ★5 ≈ 5 万文；打木桩只能练到 3 级）。
2. **装上才生效**：效果跟在「占着内功格的那部内功」身上，**卸下立刻失效**、不留残留。
   这是它和「图鉴奖励（每收 5 部 +1 属性，跨周目继承）」的分工——**图鉴管积累，内功满级管这一场的搭配**。
3. **同一种效果多来源取最高、不叠加**（两个心法都给破架势加成时只吃高的那条）；派生值本身的上限照 `stat_def` 夹。
4. **一条一个签名**：每部内功的满级效果都不一样，且**改的是打法**（段数／异常／破绽／拆招／反击／资源循环），
   不是「+X 点属性」。

**成本分批**：**甲**＝只用现有派生值与现有结算点；**乙**＝在已有流程里加一处判断（受击／命中／回合末／出击前）；
