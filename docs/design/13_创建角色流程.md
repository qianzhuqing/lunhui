# 13 创建角色流程

## 一、总览

启动菜单 → 新建游戏 → **创建角色** → 进游戏。流程分两条路：

```
创建角色
├─ 使用模板（三分钟开局）
│   └─ 选出身 → 选天赋 → 起名 → 确认
└─ 不使用模板（自定义）
    └─ 分七维 → 选武器 → 选起始武学 → 选天赋 → 起名 → 确认
```

**两条路给的东西完全等价**，不存在"自定义更强"或"模板更省事所以弱"。
区别只是**你要不要自己调那七个数字**。

## 二、使用模板

### 第 1 步：选出身

从 **5 个出身**里选一个，每张卡显示：

| 卡片内容 | 来源 |
|---|---|
| 名字 | `origin_def.name_cn` |
| 玩法标签 | `origin_def.playstyle` |
| 一句话定位 | `origin_def.tagline` |
| 详细描述 | `origin_def.desc` |
| 七维 | `character_base` |
| 武器与起始武学 | `character_base.weapon_type` / `start_skill_ids` |

五个出身覆盖五个方向：

| 出身 | 玩法 | 适合 |
|---|---|---|
| 家道失落的书生 | 探索型 | 想靠判定推内容、不爱硬拼 |
| 林铁山 | 刚猛型 | 喜欢正面硬刚 |
| 苏九娘 | 毒攻型 | 喜欢铺垫后爆发的毒流 |
| 燕小七 | 刺客型 | 喜欢抢出手、暴击 |
| 白清和 | 内功型 | 喜欢堆内功与续航 |

**卡片必须显示七维与起始武学**，不能只给一句文案——玩家是在做数值选择，
光看"探索型"三个字没法判断。

### 第 2 步：选天赋

5 点，六个方向分组，见 [12_天赋系统](12_天赋系统.md)。两条路共用这一步。

## 三、不使用模板

### 第 1 步：分七维

| 规则 | 值 | 来源 |
|---|---|---|
| 总和 | **必须正好 49** | `growth_const.create_attr_total` |
| 单项下限 | 3 | `create_attr_min` |
| 单项上限 | 15 | `create_attr_max` |

七项**全部可分配，包括悟性与根骨**。

> 注意这跟「升级不能加资质」不矛盾：
> **创建时能定资质，升级时不能再加。** 资质是「你生来是什么材料」，
> 出生时当然由你定，之后就只能靠图鉴奖励与奇遇提升。

界面上要给**剩余点数**实时显示，并且「加了没加满」与「超了」要能一眼看出来。
建议做成滑块或加减按钮，**不要做成输入框**——输入框要处理非法输入，
而这条 49 点是硬约束。

### 第 2 步：选武器

四种：剑／拳／刀／枪（`weapon_type_def`）。

武器决定**能用哪一类招式**，所以要顺带把该武器系的 ★1 招式预览给玩家看，
否则玩家不知道选刀意味着什么。

### 第 3 步：选起始武学

从**该武器系**的 ★1 招式里选 **1 部**（`skill_base` 里 `star=1` 且
`weapon_type` 匹配、或 `any` 的行）。

限定 ★1 是有意的：起始武学是「你家里/师门教的那一手」，
不该一上来就能挑绝学。

### 第 4 步：起始装备

**不由玩家选**，按武器自动给「该武器的凡品 + 布衣」
（与模板路线同一口径，见 09 号文档：入队自带武器与上衣）。

让玩家在创建界面挑装备是伪选择——凡品装备之间的差别小到玩家无法判断，
只会增加一张没有信息量的列表。

### 第 5 步：选天赋 → 起名 → 确认

与模板路线相同。

## 四、两条路的共同点与差异

| | 使用模板 | 不使用模板 |
|---|---|---|
| 七维 | 由出身给定 | **自己分（总和 49）** |
| 武器 | 由出身给定 | **自己选** |
| 起始武学 | 由出身给定 | **自己选（本系 ★1）** |
| 起始装备 | 自动给武器＋上衣 | 同左 |
| 天赋 | 5 点自选 | 5 点自选 |
| 耗时 | 约 1 分钟 | 约 3–5 分钟 |

## 五、队伍怎么凑

**选了谁当主角，谁就不作为同伴出现**——剩下的四个按 `recruit_def` 的条件陆续加入。

| 你选的主角 | 队伍构成 |
|---|---|
| 书生 | 书生 ＋ 燕小七 ＋ 林铁山 ＋ 苏九娘（＋白清和） |
| 燕小七 | 燕小七 ＋ 书生 ＋ 林铁山 ＋ 苏九娘（＋白清和） |

**无论选谁，都能凑齐 4 人**（`MAX_PARTY`），不会因为选了某个人导致队伍少一个。

**书生的「填充位」规则（0.30.0 定，见 [21_角色背景设定](21_角色背景设定.md) §五）**：
`recruit_def` 的**主键是 `char_id`**，一个角色只能有一行，所以**不能"给书生再加一行"**。
正确做法是**删掉 `RecruitService._ready_rows()` 里对 `is_initial` 的跳过**（**已落 2026-10-04，决策 289**）——
书生那一行照样按 `flag_board_read` ＋ `scene_qingfengyi` 入队，而主角是书生时
`state.char_ids.has()` 会把他跳过。**效果：他要么是主角，要么是队友。**

这也让「选谁当主角」有了第二层含义：不只是你自己怎么玩，
还决定了队伍里少谁、多谁。

## 六、界面要点

| 要点 | 说明 |
|---|---|
| 随时可返回上一步 | 创建过程不该有不可逆的操作 |
| 顶部常驻「剩余天赋点」与「剩余属性点」 | 两个配额同时存在，别让玩家记 |
| 出身卡显示七维条形图 | 五个出身一眼可比，比读数字快 |
| 确认页汇总全部选择 | 让玩家在进游戏前再核对一次 |
| **不进游戏就不能算完成** | 创建中途退出＝不落盘，避免半成品存档 |

最后一条是存档纪律：现有的存档结构里 `char_allocations` 与天赋都是角色的一部分，
**创建没走完就不该写存档**，否则会出现「主角属性全 0」的坏档。

## 待确认

1. 自定义路线要不要**预设几个「倾向」按钮**（如「偏武」「偏智」一键分配）？
   现在只做纯手动。加预设的好处是手残玩家也能快速分完，
   代价是多一层交互。
2. 出身卡的七维条形图上限取多少？建议按 `create_attr_max`（15）取，
   这样 5 个出身之间的差距能看出来，也不会因为某个出身特别高而把其他压扁。
