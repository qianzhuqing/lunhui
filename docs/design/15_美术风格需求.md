# 15 美术风格需求

> 本文定**风格与技术规格**；每张图里要有什么、命名与地图验收见
> [07_地图资源需求](07_地图资源需求.md)（地编侧）。

## 一、风格定位：墨色江湖

**低饱和的像素武侠。** 基调是「雨后的青灰石阶」而不是「明亮的卡通小镇」。

| 维度 | 取向 |
|---|---|
| 表现 | **像素**（延续当前 32px 瓦片规格） |
| 气质 | 清冷、写实向、克制。不要明亮卡通 |
| 光影 | 低对比，靠色相区分而非明度；光源统一自左上 |
| 线条 | 轮廓用墨黑系，不用纯黑；描边只在角色与可交互物上 |

### 为什么选像素而不是手绘

| | 像素 | 手绘 2D |
|---|---|---|
| 与现有资源 | **直接延续**（当前已是 32px 瓦片） | 全部重做 |
| 单人/小团队成本 | 低 | 高 3–5 倍 |
| 动画帧成本 | 低（8 帧一组够用） | 高 |
| 换皮风险 | 低，逐步替换即可 | 一次性投入 |

**当前只是占位资源**（Kenney Tiny Town，CC0），换正式资源本来就要重做一遍；
选像素是让这一步**可以分批做**，而不是押上一次性的大投入。

如果之后要改手绘，代价是：全部瓦片与角色重画、图集规格重定、
UI 与图标的风格线也要跟着换。**这会是一次重启，不是一次升级。**

## 二、色板

主色与辅色固定，强调色克制使用。

| 角色 | 色系 | 用途 |
|---|---|---|
| 主色 | 青灰（石／瓦／天） | 地形、建筑的主体 |
| 辅色 | 赭石（土／木／皮） | 道路、木构、装备 |
| 强调 | 朱红 | **只用于**血、灯笼、旗帜、敌意标记 |
| 轮廓 | 墨黑 | 角色描边、UI 边框 |
| 禁用 | 高饱和大面积纯色 | 会立刻把画面拉回卡通 |

**朱红是最贵的一格颜色。** 玩家靠它判断"哪里有危险／哪里是重点"，
所以它不能用来装饰。绿色同理（毒），金色（精英）。

可交互物要**在低饱和背景里明显跳出来**——宝箱、木桩、NPC 都用暖色提亮，
这是玩法需求不是美术偏好：玩家找不到校场就是因为这类东西不够显眼。

## 三、技术规格

| 项目 | 规格 | 来源 |
|---|---|---|
| 基础瓦片 | **32 × 32 px**，无间距（packed） | 07 §一（与工程现状一致） |
| 设计分辨率 | **1152 × 648** | 版式预算上限 |
| 渲染器 | Forward Mobile（D3D12） | `project.godot` |
| 图集上限 | **2048 × 2048**，单图集不超过 8MB | 移动端显存 |
| 通道 | PNG，32 位带透明 |
| 缩放 | 整数倍（NEAREST 采样），**禁止非整数缩放** | 像素风硬要求 |
| **字体** | **`ark-pixel-font`（字体 OFL-1.1，泛中日韩；仓库代码才是 MIT）**，见 [17_参考资料](17_参考资料.md) | 中文字形是像素风的前置条件 |

**禁止非整数缩放**这条要写死：像素图一旦按 1.5× 这类比例缩放，
会出现宽窄不一的像素，整个画面会"糊"。渲染时要么 2× 要么 3×。

### 字体要先落地

**中文像素字体是像素武侠的前置条件，不是配套设施。**

市面上绝大多数像素字体只覆盖拉丁字母，中文字形有几万个，
能覆盖简繁的像素字体屈指可数。**字体不到位的后果是整套界面退回系统字体**，
像素风立刻不成立——图再像素也没用。

已选 **`ark-pixel-font`（OFL-1.1 授权，覆盖泛拉丁与泛中日韩；随包带 `OFL.txt` 即可商用）**，
调研过程与授权对比见 [17_参考资料](17_参考资料.md)。

字体使用三条：

| 要求 | 说明 |
|---|---|
| 字号取原生尺寸 | 12／14／16 等，**不缩放字体** |
| 配一份回退字体 | 避免缺字时显示方框 |
| `assets/fonts/` 带 LICENSE 原文 | 字体最容易"随手下载就用"，也最容易被追责 |

### 4.4 界面

**这是当前最缺的一块**——项目现在整套界面用的是引擎默认外观，
没有主题资源、配色零散写在代码里。本节是给美术的完整规范。

#### 配色

**2026-10-04 修订：面板改「宣纸浅色」，原先那张深色色值表整段作废。**
原因是两套皮肤并存：本节原写深色（面板底 `#1E2224`），而用户拿去当 demo 验收、并明确要求
「至少带点水墨画的感觉」的 12 屏示意图是**宣纸浅色**——程序照本节做，被用户判成
「完全没有符合策划的 UI 示意图」。**结论：色值以示意图为准**（示意图本体在仓库外，
见 `docs/dev/UI示意落地清单.md` 开头那段地址）；**结构与跳转仍以 14 号为准**。

「**面板不能和地图抢视线**」这条原意保留，只是改由**顶栏**承担：顶栏是**唯一的大块深色**，
面板与底栏走宣纸——浮层本来就是玩家此刻要看的东西，底下的地图本就被压住了。

#### 字号：只有两档

**中文像素字体最小可用字号是 12px**（笔画密度决定的，再小就糊成一片）。
所以 UI 只有两个字号档，**两档都从同一份 12px 字集整数倍放大**：

| 档 | 字号 | 倍率 | 用途 |
|---|---|---|---|
| 标题 | **24px** | 12px × 2 | 界面标题、地名 |
| 正文 | **12px** | 12px × 1 | 其余全部（**含按钮**） |

> **本项目 UI 不做整体 2× 放大（0.32.0 拍板，Q82）**：`project.godot` 是
> `window/stretch/mode="canvas_items"` 且**没设 `scale`**——画布 1152×648 **就是**实际显示尺寸，
> 所以**主题里的字号＝玩家看到的字号**。13 个场景的 `LAYOUT`／`CONTENT` 预算（如创建角色
> 808×634，上限 1152×648）也是按 12px 正文量的；两档整体翻倍等于**整套 UI 重排**，本轮不做。

> **不再有 16px 档（A11 的原意保留，数字修订）**：字体只有 12px 一份字集，16 ＝ 12×1.33，
> 像素字会发虚；A11 说的「不碰上游废弃的 16px 尺寸」仍然成立。它原先给的
> 「标题 36px（×3）」按本条改成 **24px**——1× 体系里 36 会顶到布局，也超出这套字集的可用倍率。
> 实机试排见 `docs/dev/images/字体落地_试排.png`（同一页里 12／24／36px 清晰、13px 明显糊）。

> **按钮并入正文档（12px）——2026-10-04 Q82 收口**：按钮原先列在标题档，但程序实测把它升到 24px
> 会顶破三处版式（`battle` 满招式 1620×735、结算卡 683、`creation` 667，上限都是 1152×648）——
> 那是**另立项的一轮 UI 版式**，不在本轮。所以按钮随正文档走 12px，界面标题仍旧 24px。

> **游戏内浮字也吃这两档（2026-10-04）**：战斗里漂浮的伤害数字（`battle_screen.gd` 的 `Float_*`）原先写
> 16px——16 ＝ 12×1.33 会发虚，与「取消 16 档」是同一条理由。它归进**标题档 24px**；嫌大宁可落回 12，
> 不留 16。**这条有门限盯着**：`tests/test_handshake_repo.gd::_check_font_size_tiers` 扫
> `scenes/*.tscn`／`src/**/*.gd`／theme 里的**字面量**，**只许 12／24**（`0` ＝ 不覆写，放行），
> 别的当场红。要加第三档先改本表。

**层级不能靠字号区分，只能靠颜色**（正文／次要／禁用三级）。
这条要提前知道，否则做 UI 时会一直想"这里能不能再小一号"——不能。

### 4.5 特效

| 特效 | 说明 |
|---|---|
| 命中／暴击 | 暴击要明显强于普通命中，玩家靠它判断出手质量 |
| 异常状态 | 中毒（绿）、灼伤（橙）、流血（红）、内伤（紫）各自的跳字与粒子 |
| 增益减益光环 | 战斗中常驻面板之外的轻量表现 |
| 破架势 | **架势条打空要有一个明确的爆发瞬间**——这是核心循环的爽点 |

### 4.6 主角立绘

**主角需要立绘，但初期留白、后面统一补上。**

| 项目 | 规格 |
|---|---|
| 规格 | **320 × 480**（比例 2:3），PNG 带透明 |
| **原生分辨率** | **80 × 120**，显示时 **4 倍**放大到 320×480 |
| 位置 | 创建界面**右侧**、角色面板**左侧** |
| 数量 | 5 张（对应 5 个出身） |
| 换装 | 本章不做；立绘不随装备变化 |

### 原生分辨率要小，放大要整数倍

**这是像素立绘最容易做错的地方。**

如果按 320×480 原生画，立绘的像素颗粒会比地图细得多——
地图上的一格是 32px 放大后的粗像素，立绘却是细密的小点，
**并列时一眼就能看出不是一套东西**。这就违背了「立绘也走像素风」的初衷。

所以：**原生 80 × 120，显示时整数倍放大 4 倍。** 颗粒量与地图同量级。

> 具体放大倍数要与地图的显示缩放对齐。以 32px 瓦片在 1152×648 下的实际缩放
> 为准，取最接近的整数倍（2×／3×／4×），**不要用 1.5× 这类非整数**。

**初期不能用纯空白。** 空白框会让玩家以为是 bug，也会让版式看起来没做完。
统一用**人形剪影占位图**（所有角色共用一张），后期按同名替换——
和像素资源同一套机制（见第六节）。

**这是版式改动，不是加图。** 两个界面都要预留 320×480：

| 界面 | 影响 |
|---|---|
| 创建角色 | 出身卡与七维条形图要让出右侧空间 |
| 角色面板 | 立绘在左，属性与装备在右 |

**必须过版式预算**：整页最小尺寸仍要 ≤ 1152×648。
480 的立绘加上标题与底部说明，留给内容的只有 600 上下——
**这两处版面会很紧，加任何一行都要先想清楚从哪儿腾。**

## 五、换瓦片集的影响

当前的 Kenney Tiny Town 是**明亮卡通**，与「墨色江湖」取向相反，**决定换**。

### 换 = 六张图重铺

| 图 | 规模 |
|---|---|
| `overworld` | 大地图，最大 |
| `scene_qingfengyi` | 清风驿（城镇） |
| `scene_heifengzhai` | 黑风寨副本（三层＋隐藏层） |
| `scene_cave` | 塌陷山洞 |
| `scene_huangcun` | 荒村 |
| `scene_ferry_locked` | 废弃渡口 |

**不只是换一张图集**：新瓦片集的索引与旧的完全不同，
所以「哪些瓦片挡路」要重勾一遍，地图脚本里的瓦片坐标常量也要重写。

### 新瓦片集必须满足的规格

规定这些不是洁癖，是为了让换皮**尽量接近机械替换**：

| 规格 | 要求 |
|---|---|
| 尺寸 | 32 × 32，**无间距**（packed） |
| 结构 | 物理层 0 ＋ 自定义数据层 `blocked`，与现有完全一致 |
| 命名 | 图集文件名与现有一致（`tilemap_packed.png`） |

只要这三条对上，地图脚本改动就只剩「瓦片索引常量」一处。

### 建议：先铺一张样板

**先只铺清风驿**，确认风格、规格、挡路数据都对，再铺其余五张。

换瓦片集的风险集中在「风格对不对」和「索引对不对」两件事上，
而这两件事在最小的城镇图上就能暴露。先铺大地图的话，
一旦风格不合适，那张最大最贵的图就白做了。

## 六、命名与交付

### 命名要和配置表 id 对齐

这是**硬要求**，不是偏好：程序侧按 id 找图，对不上就加载不到。

> 下表路径都**相对 `assets/`**（只写 `tilesets/`、`sprites/` 这样的子路径）。
> 这一栏故意不带 `assets/` 前缀：开发侧的门限把「带目录前缀的路径」当成
> **现在就必须存在**的指针，而这批资源是**将来才建**的。

| 资源 | 路径（相对 `assets/`） | 例子 |
|---|---|---|
| 瓦片集 | `tilesets/<pack>/` | `tilesets/ink_jianghu/` |
| 角色 | `sprites/<faction>/<id>.png` | `sprites/bandit/en_bd_thug.png` |
| 武学图标 | `icons/skill/<skill_id>.png` | `icons/skill/sk_xuanwei_01.png` |
| 装备图标 | `icons/equip/<equip_id>.png` | `icons/equip/eq_sword_01.png`｜**A14（0.31.1 定）**：`equip_base` **补一列 `icon`**（值＝`equip_id`，与 `item_base` 同形），程序侧用它取图——**加列是开发侧的活**；美术**先按 `equip_id` 出图即可**，列落地后值相同、不用改文件名 |
| 物品图标 | `icons/item/<item_id>.png` | `icons/item/item_iron.png` |
| 增益图标 | `icons/buff/<buff_id>.png` | `icons/buff/buff_guard.png` |
| 七维图标 | `icons/attr/<attr_id>.png` | `icons/attr/str.png`（**2026-10-04 定**：`attribute_def` 七行，按行 id） |
| 派生数值图标 | `icons/stat/<stat_id>.png` | `icons/stat/atk_phys.png`（**2026-10-04 定**：`stat_def` 逐行，按行 id） |
| 空装备槽占位 | `icons/slot/slot_<slot_id>.png` | `icons/slot/slot_weapon.png`（**2026-10-04 定**：七个槽各一张空框。**不放进 `icons/equip/`**——那个目录有硬门限「每张 png 都必须是 `equip_base` 的 id」，空槽不是装备） |
| 界面 | `ui/<panel>/` | `ui/battle/` |

### 交付方式：按同名替换，不改代码

**正式资源必须能按同名文件直接替换占位资源，代码一行不改。**

音频侧已经这么做了（占位音是按事件名合成的，换同名文件即可）。
美术沿用同一条：程序侧只认路径与文件名，**不认"这张图长什么样"**。

这条对协作方式的影响很大：**美术可以分批交付**——
先换地形，再换角色，最后换 UI，每一步都可以单独验收、单独上线。

## 七、验收

| 检查 | 方式 |
|---|---|
| 规格与命名 | 文件名与配置表 id 对齐、尺寸符合上表 |
| 渲染正确 | `tools\run_windowed_smoke.bat`（真窗口跑全部场景自检） |
| 界面无裁切 | 各面板自检的 `LAYOUT` / `CONTENT` 两个预算 |
| 界面不出现表内 id | `COPY id_tokens=0` |
| 像素缩放 | 目测确认是整数倍 |

**贴图、字体、界面改动之后必须跑一次真窗口冒烟**——headless 抓不到
贴图导入、着色器、字体这类只在渲染路径上暴露的问题。

## 八、优先级

按"玩家最先看到、最能感知"排序：

| 顺序 | 内容 | 理由 |
|---|---|---|
| 1 | 主角 5 人 + 战斗界面 | 玩家看的时间最长 |
| 2 | 清风驿地形与建筑 | 开局第一眼 |
| 3 | 图标（武学与装备） | 面板里的信息密度全靠它 |
| 4 | 黑风寨地形 | 第一章主战场 |
| 5 | 特效 | 有前面打底之后，特效的收益才最大 |
| 6 | 立绘与过场 | 最后做 |

> **优先级修正（0.31.1／0.31.2，实机反馈）**：**UI 那一批提到第 1**（§4.4）——玩家一进游戏先看到界面，
> 而当时的界面是**引擎默认外观**（用户直接点了「UI 过于简陋」）。
> **正式顺序：UI → 山脉／洞口·岩缝／路牌 → 武学图标 → 装备图标 → 物品图标 → 异常 → 增益 → 派生 → 特效。**
>
> **为什么"山脉／洞口／路牌"插在图标前面**（0.31.2 补）：它**挡着地编**——
> 大地图重做（2048×1536＋相机 2×＋兴趣点融入地形）验收的就是用户那条「洞穴孤零零」的反馈；
> 而**武学图标不挡任何人**（面板有图才摆，没图的那些只是不显示，不报错）。
> **这三样先出，地编才能收口。**
>
> **UI 这一块分两半，别等美术的那一半**：
> ① **不需要任何贴图的那半**——面板底色／描边／正文／次要／禁用／强调色、按钮四态、
> 两条字号档、三条状态条颜色（§4.4 的色值表）**可以先用一个 `Theme` 资源落下来，程序当轮就能做**；
> ② **要美术的那半**——九宫格底板（切图 32×32）、边框装饰、图标。**①做完，"简陋"就解决大半。**

**图标的出图顺序（A15，0.31.1 定）**——按"玩家最先看到 + 面板信息密度"排：

| 顺序 | 批次 | 数量 | 为什么排这儿 |
|---|---|---|---|
| 1 | **武学图标** | **65** — ✅ 已全交（内功 30 ＋ 招式 35） | 角色面板与战斗里出现频率最高；15 §八 本来就把"图标"排在第 3 |
| 2 | **装备图标** | **27** — ✅ 已全交 | 与武学图标**同框出现**（角色页／行囊），分两批会让面板一半有图一半没图 |
| 3 | 物品图标 | **23** — ✅ 已全交（含新增的 4 本秘籍 `item_book_chensha`／`_tieqiang`／`_liehuo`／`_taixu`） | 同上，行囊页 |
| 4 | 异常状态图标 | **4** — ✅ 已全交（中毒／灼伤／流血／内伤） | 战斗里要**一眼认出**，量最小 |
| 5 | 增益减益图标 | **19** — ✅ 已全交（这 19 行 `is_debuff` 全 0，实际全蓝） | 同上，量中等 |
| 6 | 派生数值图标 | ~28 — **下一批**（外加七维 7、空槽占位 7，见交接单 §九） | 只在角色面板的属性页用，最小 |

## 已定口径（2026-10-04）

| # | 决定 | 影响 |
|---|---|---|
| 1 | **像素**，不做手绘 | 延续 32px 规格，资源可分批替换 |
| 2 | **主角要立绘，初期留白** | **版式改动**：创建界面与角色面板要预留 320×480 |
| 3 | **换瓦片集** | **地编返工**：六张图重铺 ＋ 重勾挡路数据 |

第 2、3 条都会牵动已经做完的东西，各自的应对写在 4.6 与第七节。

### 立绘两条补充口径（2026-10-04）

**一、立绘也走像素风。** 与地图、角色同一套像素语言，不做精细插画——
这样不存在"插画与像素并列割裂"的问题。

连带的技术要求见 4.6：**原生 80×120、放大 4 倍**。
按原生 320×480 画会让颗粒比地图细得多，同样割裂。

**二、暂不做表情差分。** 每人 1 张（常态），后续需要再加。
