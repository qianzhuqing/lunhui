# 01 角色系统

## 等级与经验

角色有等级，升级获得属性点，玩家自由分配。

| 项目 | 设定 |
|---|---|
| 每级自由点数 | **5 点**（只能力／体／敏／智／运，见下） |
| 资质 | 悟性与根骨**不能加点**，创建时定死 |
| 第一章等级区间 | 1–15 级 |
| 全程预期等级 | 15–20 级 |
| 满级 | 20 级 |

经验需求、基础属性成长见配置表 `level_growth.csv`。经验值建议由公式生成，表只覆盖关键等级。

## 成长的四条轴

变强拆成四条互不替代的轴，任何一条拉满都不够用：

| 轴 | 提供什么 | 上限 | 主要来源 |
|---|---|---|---|
| 升级 | 属性点、基础气血内力 | 20 级 | 战斗经验 |
| 武学 | 招式与内功的实战能力 | 槽位上限 | 收集＋修炼 |
| 装备 | 属性点与派生数值 | 7 槽位 | 打怪、铁匠铺 |
| 图鉴 | 七项属性加成 | +10 | 累计收集武学数量 |

四条轴的瓶颈不同：升级受经验限制，武学受槽位限制，装备受掉落限制，图鉴受内容量限制。
所以「我卡住了该干嘛」永远有答案。

## 武学成长

武学分两类，占用**两套独立的槽位**：

| | 招式（主动） | 内功（被动） |
|---|---|---|
| 性质 | 战斗中施放，消耗内力 | 装备即生效 |
| 武器要求 | 绑定武器类型（剑／拳／刀／枪，或 `any`） | 无 |
| 容量 | `slot_active`（个数） | `passive_capacity`（容量点） |
| 冲突 | 无 | 无，改为占格制 |

配置见 `skill_base.csv`（身份与门槛）、`skill_active.csv`（招式数值）、
`skill_passive.csv`（内功路数与被动）、`skill_passive_stat.csv`（内功加成）。

### 槽位上限

```
招式槽上限 = 2 + floor(等级 / 5) + floor(悟性 / 8)     硬上限 9
内功容量   = 2 + floor(等级 / 6) + floor(根骨 / 10)    硬上限 7
```

常数配在 `growth_const.csv`，算法在代码里。采样点：

| 场景 | 招式槽 | 内功容量 |
|---|---|---|
| 1 级书生（悟 10／根 5） | 3 | 2 |
| 20 级、完全不投资资质 | 7 | 5 |
| 20 级、专注悟性 30 | **9（满）** | 5 |
| 20 级、专注根骨 25 | 7 | **7（满）** |

注意内功那一列是**容量点**不是部数——1 级时只有 2 格，装不下一部 ★3 内功。

要让某一路拉满，必须牺牲另一路。这就是槽位设计的全部意义。

等级本身只贡献大约三分之一，所以「升级只是成长的一部分」在数值上成立：
20 级完全不投资资质的角色，两种槽都差得远。

### 内功容量

内功**不互斥**，改成占格制：每部内功按品阶占 1~3 格。

| 品阶 | 星级 | 占格 |
|---|---|---|
| 低级 | ★1–★2 | 1 格 |
| 高级 | ★3–★4 | 2 格 |
| 顶级 | ★5 | 3 格 |

第一章 24 部内功的占格分布：

| 占格 | 部数 |
|---|---|
| 1 格（★1–★2） | 11 |
| 2 格（★3–★4） | 11 |
| 3 格（★5） | 2 |
| **合计** | **39 格** |

容量上限只有 7 格，最多装下全部内功的约五分之一。

**这比互斥好在哪：** 互斥是「要么这部要么那部」的硬开关，容量是连续取舍。
玩家可以在「两部顶级（6 格）加一部低级」和「七部低级」之间自由选，
深度流和广度流都是合法 build，不会被规则一刀切死。

开局容量只有 2 格，连一部顶级内功都装不下——这就是根骨的现实价值。

### 星级

星级同时表达强度与获取难度。

| 星 | 定位 | 熟练度成长 | 修习门槛 | 打坐基础费用 |
|---|---|---|---|---|
| ★1 | 基础 | ×1.50 | 无 | 50 |
| ★2 | 常见 | ×1.45 | 属性 8 | 90 |
| ★3 | 稀见 | ×1.40 | 属性 12 | 160 |
| ★4 | 珍贵 | ×1.30 | 属性 18 | 280 |
| ★5 | 绝学 | ×1.25 | 属性 25 | 450 |

熟练度成长是**递减**的，这是刻意的：

```
招式实际倍率 = 基础倍率 × (1 + 熟练度 × mastery_gain)
```

★1 练满 ×1.5，★5 练满只有 ×1.25。低星武学成长快，满熟练后不会沦为垃圾；
开局拿的起手式练到后面依然能用，避开武侠游戏「新招式一出旧招式全废」的老毛病。

修习门槛要求某个属性达到阈值才能学，让悟性与根骨不只管槽位数量。

### 熟练度（修炼）

每部武学独立熟练度 0 → 10，三种提升方式：

| 方式 | 效率 | 消耗 |
|---|---|---|
| 战斗中施放 | 慢 | 无 |
| 打坐修炼（客栈／门派） | 快 | 铜钱，随熟练度递增 |
| 秘籍灌注 | 一次性 | 稀有材料 |

打坐费用 = `cultivate_cost_base × cultivate_cost_growth^(熟练度-1)`，
把一部武学从 1 练到 10 是一笔真实开销，不是顺手就满。

### 收集本身也是成长

```
每累计收集 5 部武学 → 七项属性各 +1，最多 +10
```

图鉴进度写进**全局存档**（跨周目继承），所以捡到一本用不上的秘籍也有价值。
`codex_step` / `codex_bonus` / `codex_cap` 三个常数配在 `growth_const.csv`。

### 第一章武学规模

| 类别 | 数量 |
|---|---|
| 招式 | 35 |
| 内功 | 24 |
| 合计 | 59 |

够撑满图鉴奖励的 10 次（每 5 部一次，共需 50 部）。

## 属性分层计算

最终属性分四层计算，顺序不能变：

```
最终属性 = ( 基础值 + 等级成长 + 加点 + 装备固定值 + 心法固定值 ) × ( 1 + 百分比加成总和 )
```

**这条结构必须一开始定死。** 如果后期把装备加成和基础值混在一起加，改配表会牵一发动全身。

## 七维属性

职能划分的关键是**不重叠**，七项各管一摊，玩家一眼能看懂自己在 build 什么。

| 属性 | 主职能 | 次要 |
|---|---|---|
| 力 str | 外功伤害、破架势值 | 装备力量需求；事件判定（体力活） |
| 体 con | 气血上限、外功防御、内伤抗性 | 每回合气血回复；事件判定（硬扛） |
| 敏 agi | 身法（出手顺序）、命中、闪避 | 背袭加成；事件判定（身法活） |
| 智 int | 内功伤害、内力上限与回复、异常状态强度 | 上状态的命中；事件判定（眼力活） |
| 运 luk | 暴击率、暴击伤害、异常触发率 | 掉落几率（小额）；事件判定（赌运） |
| 悟性 wu | **招式槽上限**、熟练度成长速度 | 高星武学的修习门槛 |
| 根骨 gen | **内功槽上限**、内力上限 | 高星内功的修习门槛 |

### 资质：悟性与根骨不能加点

**七维分两类，加点只能碰其中一类。**

| 类别 | 属性 | 加点 |
|---|---|---|
| 五维 | 力／体／敏／智／运 | **可加点**，每级 5 点自由分配 |
| 资质 | 悟性／根骨 | **不可加点**，创建时定死 |

**为什么把资质锁死**：悟性决定招式槽、根骨决定内功容量，它们是
「你能走多宽」的上限。如果这两项也能加点，最优解永远是先堆资质再堆输出，
中间没有任何取舍——加点就退化成一道算术题。

锁死之后，**资质决定天花板、等级决定成长速度**：

```
招式槽上限 = 2 + floor(等级 / 5) + floor(悟性 / 8)
```

悟性是固定项（开局就定），等级是成长项。所以低资质角色靠等级也能把槽位撑起来，
高资质角色则早一步到顶。**差的是"早到晚到"，不是"有没有"。**

**资质怎么提升**（三条正道，都不是加点）：

| 途径 | 说明 |
|---|---|
| 图鉴奖励 | 每收集 5 部武学，七项属性各 +1（含悟性与根骨），上限 +10 |
| 特定内功 | 例如玄微心法·太清给悟性 +5 |
| 后续章节的奇遇与丹药 | 第一章暂不开放 |

### 为什么是七条而不是五条

悟性与根骨是新加的资质，把「能带多少武学」拆成两个独立方向。

只加一条的话，武学容量就变成一个必然拉满的指标，所有 build 会趋同，反而失去取舍。
两条才能分出招式型（悟性）、内功型（根骨）、均衡型三条路线。

这就是防止膨胀的正确做法：不是简单压上限，而是让上限本身构成选择。

七维之后每级还是 3 点，专精的代价变高，加点的取舍才真实。

### 三条刻意的取舍

**暴击全给运，敏碰都不碰。** 敏管命中和出手顺序，运管暴击和运气。很多游戏把暴击分给敏和运两个属性，结果玩家两边都得堆，反而没有取舍。

**异常状态拆成两半：强度归智，触发率归运。** 智决定毒有多狠，运决定毒有多爱上身。想玩毒流，两个属性都得管，这就是一条独立的 build 路线。

**智只管内功伤害，不管"通用招式倍率"。** 如果智加成所有技能伤害，它就成了万能属性，谁都得堆。招式倍率挂在武器和武学上，不挂在属性上。

## 战斗属性

战斗属性是五维、装备、心法、词条汇聚出来的派生数值，**不能直接加点**。
完整定义见 `stat_def.csv`，属性到数值的换算见 `attr_to_stat.csv`，
结算用到的全局常数见 `combat_const.csv`。

### 攻击侧

| stat_id | 名称 | 说明 | 主要来源 |
|---|---|---|---|
| `atk_phys` | 外功攻击 | 外功系伤害基数 | 力 |
| `atk_qi` | 内功攻击 | 内功系伤害基数 | 智 |
| `crit_rate` | 暴击率 | 触发暴击的概率 | 运 |
| `crit_dmg` | 暴击伤害 | 暴击时的额外加成 | 运 |
| `pen_rate` | 穿透率 | 按比例无视目标防御 | 力、装备 |
| `poise_break` | 破架势 | 削减敌方架势的效率 | 力 |
| `hit_rate` | 命中率 | 攻击命中概率 | 敏 |

### 防御侧

| stat_id | 名称 | 说明 | 主要来源 |
|---|---|---|---|
| `def_phys` | 外功防御 | 减免外功伤害 | 体 |
| `def_qi` | 内功防御 | 减免内功伤害 | 装备 |
| `block_rate` | 格挡率 | 触发格挡的概率 | 体、装备 |
| `block_reduction` | 格挡减伤率 | 格挡成功时的额外减免 | 装备 |
| `dmg_reduction` | 减伤率 | 最终伤害的常驻减免 | 装备 |
| `dodge_rate` | 闪避率 | 完全躲开攻击的概率 | 敏 |
| `res_internal` | 内伤抗性 | 抵抗内伤类效果 | 体 |

### 资源与行动

| stat_id | 名称 | 说明 |
|---|---|---|
| `hp_max` / `hp_regen` | 气血上限 / 每回合回复 |
| `qi_max` / `qi_regen` | 内力上限 / 每回合回复 |
| `speed` | 身法，决定出手顺序 |

### 结算顺序

穿透、格挡、减伤三项各自插在管线的不同位置，**顺序放错会让数值直接失衡**。
完整管线见 [04_战斗与伤害](04_战斗与伤害.md)，一句话概括：

**穿透在防御之前生效，格挡在防御之后，减伤在最后。**

### 三条设计纪律

**减伤率不给属性。** `dmg_reduction` 只能来自装备和临时效果，上限 60%。
能被属性线性堆出来的话，配合防御公式会迅速失控。

**格挡与闪避互斥。** 同一次攻击只判定一次：先判闪避（完全免伤），
未闪避再判格挡（部分免伤）。两个都触发的话坦克堆双属性后近乎无敌，战斗节奏也会拖沓。

**穿透率上限压在 75% 以下。** 穿透过高会让防御体系形同虚设，
而且它是乘在防御公式分子上的，收益曲线很陡。

以上为示意值，实际以 `attr_to_stat.csv` 为准。

**槽位上限不在这张表里。** `slot_active` / `slot_passive` 同时依赖等级与资质，
而且带硬上限，用 `attr_to_stat` 的「属性 × 系数」表达不了，所以它们走
`growth_const.csv` 里的公式常数，算法在代码中实现。这是本项目里第二种
「公式在代码、常数在表里」的派生数值，第一种是伤害管线的防御减免。

### 三条配表纪律

**百分比类一律递减，固定值一律线性。** 闪避、暴击率这种要是线性堆，后期一定堆到无解。

注意外功防御是**固定值**而不是百分比，减免比例由结算公式换算得出，所以这里走线性、不设上限。真正需要设上限的是减免结果，不是防御数值本身。

**上限（cap）写进表里。** 别指望玩家自觉，也别指望后期再想起来加。

**公式不写进表里。** 表只配 `curve` 枚举和系数，具体算法在代码里实现。把公式塞进 Excel，半年后没人看得懂那张表。

### 曲线的含义

| curve | 公式 | 用途 |
|---|---|---|
| `linear` | `eff = rate × attr` | 固定值类 |
| `diminishing` | `eff = cap × attr / (attr + param)` | 比率类 |
| `piecewise` | 按分段点线性插值 | 特殊需求 |

递减曲线用 `cap × attr / (attr + param)` 的形式，收益随属性增长自动趋缓，且永远到不了上限。`param` 在 `attr_to_stat.csv` 里配置。

## 非战斗属性与事件判定

事件判定决定玩家能不能撬开隐藏内容、避开战斗、拿到额外奖励。
它有**两套来源**：基础属性，和非战斗技能。

### 来源一：基础属性

五维本身就参与判定，不需要任何技能等级。用来过体力活、身法活、眼力活和赌运场合。

| 属性 | 判定场景举例 |
|---|---|
| 力 `str` | 搬开塌方碎石、掰断铁锁、推开石门 |
| 体 `con` | 寒夜守夜不冻伤、中毒后硬扛、长途不歇 |
| 敏 `agi` | 翻越寨墙、接住抛来的东西、在窄梁上行走 |
| 智 `int` | 识破假情报、推演棋局、快速算账 |
| 运 `luk` | 赌局、抽签、碰运气撞见某事 |

### 来源二：非战斗技能

奇门、医术、毒术、文学、生存五项，**完全不参与战斗**，只用于探索与事件判定。
它们是技能等级，来源是角色模板、书籍、事件奖励和少量装备。

配置见 `event_skill_def.csv` 与 `event_check.csv`。

| skill_id | 名称 | 关联属性 | 主要用途 |
|---|---|---|---|
| `qimen` | 奇门 | 智 | 机关、阵法、暗门 |
| `yishu` | 医术 | 智 | 救治、辨药、解读伤势 |
| `dusu` | 毒术 | 智 | 辨毒、制毒、用毒 |
| `wenxue` | 文学 | 智 | 题字、碑文、书信、交涉 |
| `shengcun` | 生存 | 体 | 追踪、找路、野外庇护 |

### 统一的判定接口

`event_check.csv` 的 `check_source` 字段带前缀，区分两套来源：

```
attr:str     → 判定值 = 力的裸值
skill:wenxue → 判定值 = 文学等级 + floor(智的裸值 / 5)
```

**判定只用裸属性，不含装备加成。** 这条是刻意的：如果装备算数，
玩家会为过一个门临时换一身力装，判定就变成了"检查背包"而不是"培养角色"。
加了点才过得去，这才叫养成。UI 显示判定值时也要标一句"不含装备"。

两套来源的难度刻度不同，配置时不要混用：

| 来源 | 判定值范围 | 难度刻度 |
|---|---|---|
| 基础属性 `attr:` | 开局 5–10，后期专精可到 30+ | 5 ~ 25 |
| 非战斗技能 `skill:` | 开局 0–5，满级约 18 | 2 ~ 12 |

### 两种判定强度

| 类型 | 规则 | 用途 |
|---|---|---|
| 硬判定 `hard` | 判定值 ≥ 难度则必定成功，不足则无法进行 | 解锁隐藏内容、关键分支 |
| 软判定 `soft` | 达标必定成功；不足可掷骰，成功率 `0.5 + (判定值 − 难度) × 0.1`，夹在 5%~95% | 额外奖励、非关键分支 |

**硬判定保证确定性，软判定给低技能玩家一次机会但不保证。**

关键是**软判定失败不惩罚**，只是拿不到额外好处。否则玩家会读档重来，
判定就失去意义了——这和存档规则里"战斗中禁止读档"是同一个考虑。

### 事件判定是隐藏内容的钥匙

第一章的七项隐藏内容里，有三项原本只能靠到处乱撞，现在改为靠判定解锁：

| 隐藏 | 判定 | 说明 |
|---|---|---|
| 后山密道 | 生存 3 | 在落雁坡追出足迹，找到塌陷山洞 |
| 三火盆密室 | 文学 5 | 读出聚义厅墙上题字的次序 |
| 毒杀毒手 | 毒术 3 | 认出毒堂里的毒酒可以反用 |

这样隐藏内容就有了**可培养的门槛**，玩家卡住时知道该去练什么，而不是碰运气。

### 一条纪律：判定不要卡在主线必经路上

硬判定卡住主线会逼玩家去刷技能，节奏直接断掉。
**`hard` 判定只用于可选的隐藏内容和分支**，主线路径永远留一条不需要判定的走法。

## Build 路线

属性职能定下来，路线自然分出来：

| 路线 | 主属性 | 打法 |
|---|---|---|
| 刚猛流 | 力・体 | 高外功直伤、高破架势，正面硬拼 |
| 毒功流 | 智・运 | 内功伤害＋中毒持续输出，需要时间铺垫 |
| 刺客流 | 敏・运 | 高身法抢出手、暴击流，靠背袭起手 |
| 内功续航流 | 智・体 | 高内力、高续航、内伤压制敌方内力 |
| 招式型 | 悟性 | 招式槽拉满，靠多套招式轮换应对不同敌人 |
| 内功型 | 根骨 | 内功槽拉满，靠多路数被动叠加属性 |

四到五条路线，够玩家玩两三个周目换着打。

后两条和前面几条**不在同一个维度上**：前四条是主属性取向，后两条是资质取向。
实际 build 是两个维度的组合，比如「毒功流 + 内功型」或「刺客流 + 招式型」。

## 平衡风险

**双攻击属性的割裂。** 力管外功、智管内功，那"混伤"装备对谁都无用，容易变成废品。解决办法是让武学决定系别而不是武器，玩家换套武学就能换输出属性。

**运影响掉落会催生"换装刷"。** 玩家会穿一身运装刷本，刷完换回输出装。这本身是经典设计，但要有意为之——要么把影响做得足够小（每点 0.3%，上限 25%），要么大方承认并做成一条正经 build。
