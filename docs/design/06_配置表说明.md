﻿# 06 配置表说明

## 目录

所有数值配置在 `data/tables/`，共 64 张 CSV（0.29.1 新增 `flavor_point`；0.31.0 起补上对话容器 `dialogue_node`／`dialogue_option`）。

## 改动工作流

**文档与配置表必须同步，这是硬性要求。**

| 步骤 | 动作 |
|---|---|
| 1 | 先改策划文档（`docs/design/`），把设计意图写清楚 |
| 2 | 再改 `data/tables/` 里受影响的表 |
| 3 | 更新本文件表清单中的行数 |
| 4 | 跑 `tools/validate_tables.ps1`，退出码必须为 0 |

常见联动：

| 改动 | 连带要动的表 |
|---|---|
| 新增属性 | `attribute_def` → `attr_to_stat` → `stat_def`（缺一不可） |
| 新增战斗属性 | `stat_def` → `attr_to_stat`（决定是否由属性驱动）→ `equip_base`（新开一列 `bonus_*`）、`affix_pool` |
| 新增非战斗技能 | `event_skill_def` → 每个角色都要在 `character_base_skill` 补初始等级 |
| 新增事件判定 | `event_check`（`check_source` 带 `attr:` 或 `skill:` 前缀） |
| 新增武器类型 | `weapon_type_def` → `equip_base.weapon_type` |
| 新增装备槽位 | `equip_slot_def` → `equip_base.slot` → `affix_pool.allow_slots` |
| 新增装备 | `equip_base` → `drop_table` / `shop_stock` → `affix_pool`（按槽位） |
| 新增商店 | `building_def` → `shop_stock`（`buy_price` 必须大于 `sell_price`） |
| 新增消耗品 | `item_base`，必须标 `use_context` 是 `field` 还是 `battle` |
| 新增武学 | `skill_base` → `skill_active`（招式）或 `skill_passive`（内功）→ `skill_passive_stat`（内功至少一条加成） |
| 调整内功占格 | `skill_passive.slot_cost`，应与星级对应（★1-2→1 格 / ★3-4→2 格 / ★5→3 格） |
| 新增属性 | `attribute_def` → `attr_to_stat` → `stat_def`；同时复核 `character_base.attr_total` 与 `skill_base.learn_req_attr` |
| 调整槽位公式 | `growth_const`，并同步 `01_角色系统.md` 的采样表 |
| 新增 buff | `buff_def` → `buff_stat`（数值型）→ `buff_grant`（谁发它） |
| 新增套装 | `set_def` → `set_member` → `set_bonus`（档位不得超过成员数） |
| 新增伤害类型 | `damage_type` → `status_effect` → `skill_base` |
| 新增敌人 | `enemy_base`（挂 `drop_group`）→ `drop_table` → `enemy_team` → `roaming_spawn` |
| 新增副本房间 | `dungeon_room`（出口要指向已存在的房间）→ `hidden_trigger` → `map_local` 的 `room_count` |
| 新增装备 | `equip_base` → `drop_table` → `affix_pool`（按槽位） |

**改表的列结构会打断开发侧的构建。** 游戏侧的行类与 CSV 列是双向严格对应的，
多一列或少一列都会构建失败。列结构变更必须同步通知开发侧补行类字段，
校验器会把这种漂移列出来（见下）。只加行、不加列是安全的。

校验器会把这些关系全部检查一遍，所以"改一半"是跑不过的。

## 通用约定

| 项目 | 约定 |
|---|---|
| 编码 | UTF-8 **带 BOM**（保证 Excel 双击不乱码） |
| 分隔符 | 逗号 |
| 首行 | 字段名，英文 snake_case |
| 比率 | **一律用小数**，`0.01` 表示 1% |
| 布尔 | `1` / `0` |
| 引用 | 填目标表的主键 id，不填名称 |
| 空值 | 留空，不写 `NULL` / `-` / `0`（0 是有效值） |
| 名称列 | 显示用中文放 `name_cn` 列，代码只读 id |

### BOM 注意事项

CSV 带 BOM 后，用代码读取时**首个字段名会带上 `\ufeff`**。加载时要剥掉：

```gdscript
var header := file.get_csv_line()
if header.size() > 0 and header[0].begins_with("\ufeff"):
    header[0] = header[0].substr(1)
```

或者干脆在导出管线里统一去掉 BOM。两种都行，但要统一，别一半一半。

## 引用关系

```
【角色】
  attribute_def + curve_def ──► attr_to_stat ──► stat_def
  level_growth ──────────────────────────────► 属性成长
  weapon_type_def ─┐
  event_skill_def ─┴──► character_base ──► character_base_skill
                              ▲
                       event_check（判定来源：attr: 或 skill:）

【战斗】
  damage_type + element_counter + status_effect ──► skill_base
  combat_const ──────────────────────────────────► 伤害管线常数

【敌人与掉落】
  skill_base ──► enemy_team ──► roaming_spawn ◄── map_region
  enemy_base ──► drop_table ◄── item_base / equip_base ──► rarity_def / affix_pool
  drop_table ──► difficulty_drop_rate ◄── difficulty_config

【世界】
  map_region ──► map_local ──► dungeon_room ──► hidden_trigger
                      └──────────────┴───────► event_check
```

## 重点表字段说明

### attr_to_stat.csv

属性到派生数值的核心映射表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 主键 |
| `attr_id` | string | 来源属性，引用 `attribute_def` |
| `stat_id` | string | 目标派生数值，引用 `stat_def` |
| `rate` | float | 每点属性提供的数值 |
| `curve` | string | 成长曲线，引用 `curve_def` |
| `cap` | float | 结果上限（第 3 步校验用） |
| `param` | float | 曲线参数，`diminishing` 时使用 |
| `note` | string | 备注 |

### level_growth.csv

| 字段 | 类型 | 说明 |
|---|---|---|
| `level` | int | 等级 |
| `upgrade_points` | int | 升到本级获得的属性点 |
| `exp_to_next` | int | 升下一级所需经验 |
| `base_hp` / `base_qi` | int | 基础气血／内力 |
| `base_atk_phys` / `base_atk_qi` | float | 基础外功／内功攻击 |
| `base_def_phys` / `base_def_qi` | float | 基础外功／内功防御 |
| `base_speed` | float | 基础身法 |

### character_base.csv

可操控角色的起点。文档原先只写了等级成长，没写角色初始五维的来源，这张表补上四层公式里的「基础值」那一层。

| 字段 | 类型 | 说明 |
|---|---|---|
| `char_id` | string | 主键 |
| `name_cn` | string | 显示名 |
| `role_tag` | string | build 路线标记（刚猛流／毒功流／刺客流／内功续航流） |
| `weapon_type` | string | 这个模板能用的武器类型，引用 `weapon_type_def`。**决定武器槽能装什么、以及哪些招式用得出**（起手招式与起始装备都要与它自洽，构建期会校验） |
| `initial_str` / `initial_con` / `initial_agi` / `initial_int` / `initial_luk` / `initial_wu` / `initial_gen` | int | 初始**七维**（0.6.0 起加了悟性 `initial_wu` 与根骨 `initial_gen`），由 `attr_to_stat` 换算成派生数值 |
| `attr_total` | int | 七维合计，**必须等于上面七列之和**（构建期逐行核；当前模板统一 49） |
| `start_level` | int | 初始等级 |
| `start_skill_ids` | string | 初始武学，多个用 `;` 分隔，引用 `skill_base` |
| `start_equip_ids` | string | 初始装备，多个用 `;` 分隔，引用 `equip_base`；**武器要与 `weapon_type` 同类、且等级门槛不高于 `start_level`**（构建期会校验） |

### damage_type.csv

| 字段 | 类型 | 说明 |
|---|---|---|
| `type_id` | string | 主键 |
| `category` | string | `instant` 直伤 / `dot` 持续 |
| `can_crit` | bool | 是否参与暴击判定 |
| `can_dodge` | bool | 是否能被闪避 |
| `use_def_phys` / `use_def_qi` | bool | 是否吃对应防御减免 |
| `tick_timing` | string | `immediate` / `turn_end` |
| `base_duration` | int | 默认持续回合 |

| `display_color` | string | 跳字颜色 |

### equip_base.csv

装备基础数值。**属性点加成与派生数值加成是两回事**，分两组列：

| 字段组 | 含义 |
|---|---|
| `attr_str` / `attr_con` / `attr_agi` / `attr_int` / `attr_luk` | 直接加属性点，会再经过 `attr_to_stat` 换算成派生数值 |
| `bonus_atk_phys` / `bonus_atk_qi` / `bonus_def_phys` / `bonus_hp_max` / `bonus_speed` / `bonus_crit_rate` / `bonus_pen_rate` / `bonus_block_rate` / `bonus_block_reduction` / `bonus_dmg_reduction` | 直接加派生数值，**去掉 `bonus_` 前缀即为 `stat_def` 的 `stat_id`**（这 10 列就是现在全部 `bonus_` 列；单条加成不许超过该数值的 `stat_def.max_value`，构建期会警告） |

`bonus_` 这套前缀只是为了让表头一眼能分清两类加成。代码读取时剥掉前缀再去查 `stat_def`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `equip_id` | string | 主键 |
| `slot` | string | **必须引用 `equip_slot_def.slot_id`**（现在是 7 类：`weapon` / `body` / `belt` / `shoulder` / `legs` / `ring` / `necklace`） |
| `rarity` | string | 引用 `rarity_def` |
| `level_req` | int | 装备等级需求 |
| `weapon_type` | string | **仅武器槽填**，引用 `weapon_type_def`；非武器槽必须留空（构建期会校验）。决定这件武器能不能被某个角色装备 |
| `element` | string | 武器系别，影响可用招式 |
| `special_effect` | string | 特殊效果 id，空为无 |
| `drop_only` | bool | 是否只能掉落获得，商店不售 |
| `icon` | string | 图标 id：**值＝`equip_id`**（与 `item_base.icon` 同形）。界面按 `assets/icons/equip/<icon>.png` 取图，**空则退回 `equip_id`**——所以"这张还没出图"不是数据错（15 §六／A14，0.31.1） |

### affix_pool.csv

装备随机词条池。

| 字段 | 类型 | 说明 |
|---|---|---|
| `affix_id` | string | 主键 |
| `target` | string | **带前缀**：`attr:` 加属性点，`stat:` 加派生数值 |
| `value_kind` | string | `attr_point` / `flat` / `rate` |
| `value_min` / `value_max` | float | 数值区间，`rate` 类用小数 |
| `allow_slots` | string | 允许的槽位，用 `\|` 分隔 |
| `min_rarity` | string | 最低出现稀有度，引用 `rarity_def` |
| `weight` | int | 抽取权重 |

`target` 用前缀是为了区分"加 2 点力"和"加 2 点外功攻击"——这两件事在计算层级上完全不同，加属性点会连锁影响多个派生数值。

### difficulty_drop_rate.csv

**"难度不影响掉落清单，只影响掉落几率"这条规则的唯一实现处。**

| 字段 | 类型 | 说明 |

| `fight_note` | string | 武取的说明 |
| `reward_group` | string | 宝箱内容，引用 `drop_table.drop_group` |

**文取的三个字段可以叠加**：`peace_item` 与 `peace_check_source` 同时填时，
满足任意一条就算过（荒村屠夫就是「给草药汤」**或**「医术判定 3 过」）。
只填一个就是单一条件；三个都空表示这个 NPC 只能打。

**无守卫的宝箱不在这张表里**——判断口径见 [09_试玩修正](09_试玩修正.md)：
箱子藏着的（靠探索或解谜才见到）不配守卫，明摆着的必须配。

## Godot 加载建议

### 目录约定

```
res://data/tables/*.csv     ← 配置源文件，进 Git
res://data/generated/*.tres ← 构建期生成，不进 Git
```

### 管线

1. CSV 作为**唯一数值来源**，设计师只改 CSV
2. 构建期跑一个转换脚本，把 CSV 转成 Godot Resource
3. 运行期只读 Resource，不读 CSV

这样做的好处：运行期不解析文本、类型安全、加载快；同时设计师仍然用 Excel 编辑。

如果跳过转换直接读 CSV 也能跑，但后期表变多、字段变复杂之后会很难受。**建议第一版就把转换脚本建起来**，成本很低，收益很大。

### 表结构与代码的边界

| 放表里 | 放代码里 |
|---|---|
| 系数、上限、倍率 | 计算公式 |
| 曲线枚举名 | 曲线算法实现 |
| 引用 id | 引用校验、加载顺序 |
| 文本、颜色、图标 | 显示逻辑 |

**公式绝不写进表里。** 表只配枚举和参数，算法在代码里实现。
