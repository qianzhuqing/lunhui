## 一、开工前必须知道的三件事

### 1. 字体要先落地，它决定整套界面的观感

**中文像素字体是像素武侠的前置条件，不是配套设施。**

绝大多数像素字体只覆盖拉丁字母，而中文字形有几万个。**字体不到位，
整套界面会退回系统字体，像素风立刻不成立**——图再像素也没用。

已选 **`ark-pixel-font`（MIT 授权，覆盖泛拉丁与泛中日韩）**，
调研过程与授权对比见 17 号文档。

代价要知道：**中文像素字体最小可用字号 12px**，所以 UI 只有两档字号、**两档都由 12px 整数倍放大**
（**标题 36px＝×3／正文 24px＝×2**），**层级只能靠颜色区分**（15 号 §4.4）。
（**A11 已定**：上游 2026.09.01 之后废弃了 16px 尺寸，那档落不了地；授权是 **OFL-1.1**，不是 MIT。）

### 2. 先做清风驿当样板，不要先铺大地图

换瓦片集的风险集中在两件事上：**风格对不对**、**索引对不对**。
这两件事在**最小的城镇图上就能暴露**。

先铺大地图的话，一旦风格不合适，**最大最贵的那张就白做了**。

### 3. 正式资源按同名替换，代码一行不改

**程序只认路径与文件名，不认"这张图长什么样"。**

好处是**可以分批交付**——先换地形、再换角色、最后换 UI，
每一步单独验收、单独上线，不用等全部画完才合进去。

音频侧已经是这么做的，美术沿用同一条。

## 三、五条容易做错的地方

**一、立绘按 320×480 原生画是错的。** 那会让颗粒比地图细得多，一样割裂。
**原生 80×120、放大 4 倍**（15 §4.6）。

**二、石隙迷窟的死路必须画得像能走。** 两处死路如果画得明显（一堵墙、
一段坍塌），**迷宫就不成立了**。塌方那间的宝箱光甚至要比别处亮一点——
**死路的"死"要由玩家走到底才发现，不能由美术提前告诉他**（16 §4.8）。

**三、塌陷山洞与石隙迷窟不要撞脸。** 两者明度相近，靠**岩壁形态**区分：
塌陷山洞破碎杂乱（塌出来的），石隙迷窟笔直有裂缝（劈出来的）；
光也相反——塌陷山洞几乎无光，石隙有一线天光（16 §5）。

**四、NPC 头像与主角立绘不能混做一份。** 立绘是全身、头像只画头肩；
把立绘缩成头像**构图不对**（脸只剩几个像素）。两者共用同一套像素语言，
但尺寸与用途不同（15 §4.2）。

**五、大地图城镇地标是 48×48，不是 32×32。** 城镇必须「最大最显眼」
（16 §3.5）：地形占地 **3×3 瓦片（硬下限 2×2）**、图标 **48×48**；
**只有副本／驿站才用 32×32**。城镇是「拼出来的地形」＋一枚 48×48 图标，
不是给整座城贴一个 32×32 的小图标。

## 四、技术规格（硬约束）

| 项目 | 规格 |
|---|---|
| 基础瓦片 | **32 × 32**，无间距（packed） |
| 瓦片集结构 | 物理层 0 ＋ 自定义数据层 `blocked`，与现有**完全一致** |
| 图集文件名 | `tilemap_packed.png`，与现有一致 |
| 设计分辨率 | **1152 × 648** |
| 图集上限 | 2048 × 2048 |
| 缩放 | **整数倍**（NEAREST），**禁止非整数缩放** |

**图集结构三条对上，地图脚本的改动就只剩"瓦片索引常量"一处**——
这是让换皮接近机械替换的关键。

**四条别做错：**

1. **立绘不是 900×1200、也不是 320×480 的画布**——按 §4.6：**原生 80×120，显示放大 4 倍到 320×480**（比例 2:3）。
2. **空槽占位不等于「画一件装备」**：它是七个槽各自的**空框**（身体／腰带／肩部／下装／戒指／项链…），
   里面只放一个部位标识，**不带任何装备的形**，否则玩家会以为那里有东西。
3. **图标不承担星级**（A15）：武学 ★1→★5 靠颜色与母题递进，**不加角标、不加边框**；星级由界面文字与颜色说。
4. **别给悬停小卡、开关滑块、套装进度点、槽位底框、分类标签底色、称号印章这六样出图**——
   它们全部程序画（§九 第二条），出了也用不上。
