# artgen：墨色江湖贴图生成器

> **本目录归「小美术1」（美术资产）维护，别的线程别动**——它是这批美术的**源文件**
> （调色板、每个瓦片的画法、每族图标的骨架都在数据里），改一处会连带重出全部输出；
> 要改先在本线程改，交接走 `docs/dev/交接/小美术1.md` ＋ `AGENTS.md` 的「当前执行者」表。

```bat
node tools\artgen\artgen.js            rem 五套瓦片集 + 迷雾 + 大地图图标 + 道具
node tools\artgen\artgen.js --maps     rem 顺带重出 docs\dev\images 下的区域地图预览
node tools\artgen\artgen.js --out DIR  rem 落到别处（改图时先看效果，别动仓库）
```

只依赖 Node 内置的 `zlib`：**不需要 Python、Pillow、Godot，也不需要联网**
（写 PNG 的那几十行在 `pixel.js` 里）。

## 为什么是「生成」而不是「导入素材」

像素画的每一笔都要可复现、可回改。生成器就是这批美术的**源文件**：
调色板、每个瓦片的画法、图标剪影全是数据，改一处重跑一次，五套图集与全部图标一起跟上。
手工改 PNG 的路线会漂移（改了 `icon_town.png`、下一批图标忘了同步），这条不会。

换真美术时仍然照 15_美术风格需求 §六：**同名覆盖**，场景与代码一行不改。

## 两条硬约束

1. **图集坐标不能动。** `tiles.js` 的 `LAYOUT` 里每个坐标都对应 `tools/mapgen/map_kit.gd`
   的 `T_*` 常量；挪一格，所有场景的 `tile_map_data` 就全指错地方，而且**不报错**——
   只是地图上长出一堆莫名其妙的东西。要加瓦片就挑空坐标加，然后同步 `T_*` 与
   主题的 `tiles`／`solid` 清单（`.tres` 的 `blocked` 与碰撞盒由 `map_kit` 生成）。
2. **主题之间只有调色板与材质语言不同。** `THEMES` 里每套主题给一组区域主色
   （16_区域美术设定 §五要求相邻区域不撞主色）＋ `groundStyle`／`wallStyle`／`floorStyle`；
   画法共用。加主题 = 加一份调色板 + 一个 `.tres` + 一个 `map_local` 行。

### 大地图的山：一条画法教训

**山体第一版是"一面灰墙"**——整片同一个色，铺到地图上完全没有厚度。第二版加了三样才立起来：

1. **纵向明暗**（上面受光、越往下越暗）——"厚度"的主要来源，靠它一眼看出这是座山；
2. **沟壑**（自左上往右下走的 2px 暗沟，断续，左缘 1px 亮）；
3. **山脊不等高**（脊线一横平立刻暴露"这是瓦片"）＋ 脊上点松。

还有一条**跟 2× 相机有关**：一屏只有约 16×9 格，所以**地形靠轮廓与明暗读，不靠细节**。
孤零零一格山在 2× 下就是一块石头——**必须成片**（至少 2–3 屏）才像山，这也是设计那句
「山脉本身要成片、有厚度」的由来。

**内功 30 张全齐**（5 张手绘的本命内功 ＋ 25 张按同一套语法生成）：

（**改的是本文件的输出键，不是文件名**——手改会被下次重跑覆盖，决策 357）。

表里 `skill_base` 共 **65 行**，拆成两半、两套画法（15 §4.3 的「同一类别内构图取齐」：
**武器类都斜 45°、内功类都正面居中**）：

| 类别 | 张数 | 表里的判据 | 构图语法 |
|---|---|---|---|
| **内功**（passive） | **30** | `skill_id` 以 `pf_` 开头（`weapon_type` 为空） | 与已交付那 5 张同一套：压暗圆底 ＋ **统一的气环**（同半径、同粗细、同一个断口）＋ 正面居中的母题 ＋ 丹田一点「息」 |
| **招式**（active） | **35** | `skill_id` 以 `sk_` 开头 | 压暗圆底 ＋ **斜 45° 的兵器剪影**（剑 12／拳 11／刀 5／枪 4／任意 3）＋ 一道方向一致的动作残影 |

**两条把 65 张拧成一套的规矩**（比单张画得漂亮重要）：

1. **同类别的「骨架」必须一模一样**：内功的气环、招式的 45° 轴与残影方向，**全类别共用同一段代码**
   （内功是 `plate()`／`qiRing()`／`breathMark()`；招式是 `plate()`／`trail45()`／`finish()`，

2. **星阶不画进图标**：同门的 1→5 星靠**颜色与母题**递进，别靠加边框／加角标——
   那是列表 UI 的活（15 §4.4 已经定了「层级只能靠颜色」），画进图标就会和别的图标打架。

**颜色**：按 `school_id`（15 个学派）取主色，同一学派内看 `star` 提亮；
15 §二那条「朱红只给血／灯笼／旗帜／敌意、绿色＝毒、金色＝精英」照旧——
所以**五毒系一律绿、朱红只在火／刀这类本来该红的招上出现**。

### 异常／增益：**亮底 ＋ 深记号**，与别的类反着画

异常 4 张（`status.js`）与后面的增益 19 张是**同一族**——它们都出现在战斗界面那条
「增益减益」chip 列表里（`battle_screen._make_effect_chip()`，chip 是 `Button`，
图标按**原生尺寸**摆在 12px 文字旁边）。所以这一族的骨架与仓库里别的图标相反：

| 族 | 骨架 | 为什么 |
|---|---|---|
| 武学／物品／装备 | **压暗圆底 ＋ 亮记号** | 面板列表里排一行，底要沉下去、不跟字抢 |
| **异常／增益** | **亮色圆底 ＋ 近黑记号** | HUD 那条 chip 很小、又要一眼认出；亮底先抓眼，色相报"是哪个" |

颜色照 15 §二：**绿＝毒**（中毒）、**朱红只给血**（流血）、灼伤用**火把橙**那一族（不是朱红）、
内伤给**暗紫**——它不是掉血是"内力被截断"，用红会和流血撞、用蓝会和增益撞。

三条踩出来的：

1. **彩底上的记号要用近黑，别用"同色系深版"**：第一版绿底配暗绿、橙底配暗橙，四种全糊成一坨
   ——**明度差才是认得出的原因，色相交给圆底就够了**。
2. **记号画在 `outline()` 之后**：勾边会给近黑的记号各包一圈墨，挨得近的还会连成一片
   （中毒那三粒泡就是这么成一坨的）。亮底上的深记号本来不需要那圈墨。
3. **中毒那三粒别摆成"两眼一嘴"**：第一版一左一右加中间一颗，16 px 下就是个鬼脸；
   改成**沿斜线往上的一串**才是"在冒泡"。灼伤同理——只画一个三角不像火，得给顶端开个豁口成两片火舌。

### 物品 23 张：三种「纸」要分得开

物品里有一堆"纸制品"，**它们会同框，所以得靠形制分开，不能都画成一张有字的纸**：

| 形制 | 谁 | 画法 |
|---|---|---|
| 整幅竹简 | `item_scroll_yipian` 遗篇残卷 | 竖条竹简 ＋ 撕角（第一张交付的） |
| 散页残页 | `item_scroll_wudu`／`item_scroll_drunk` | 一张纸、**一侧撕开** ＋ 学派墨色（绿＝毒／酒渍＝醉） |
| 线装册 | `item_book_chensha`／`tieqiang`／`liehuo`／`taixu`（Q3 商店卖谱） | 书脊 ＋ 封面 ＋ **书口那叠纸页** ＋ 题签 ＋ 包角（`bookIcon()` 一处骨架） |
| 旧账册 | `item_bd_ledger` | 旧蓝布、磨白、起毛、夹着纸条——**故意不像宝贝** |

两条踩过的：

1. **秘籍不许像账册**：账册是"一眼看不出重要"的旧本子，秘籍反过来要像"装订过的东西"
   （整封面 ＋ 题签 ＋ 包角 ＋ 书口露纸）。四本之间**靠学派色与题签记号分开，不靠加花纹**。
2. **四本里有两条蓝灰撞色**：`tieqiang` 与 `taixu` 的学派色本来就挨着（武学图标那边也一样），
   摆在一排会认混——所以铁枪留**钢灰 ＋ 一道横箍**（兵器谱），太虚让给**青瓷色**（气纹）。
   这条与武学图标是同一个毛病（黑风系那三张也踩过）：**出图前把同批摆一行比一次明度与色相**。

### 装备 27 张：和物品图标同框，就照物品的画法

装备图标落在 `icons/equip/<equip_id>.png`（`equips.js`，27 行 = `equip_base` 的行数）。
**它的邻居是物品图标**（角色页的装备栏与行囊页是同两个面板），所以沿用物品那套语言：
**透明底 ＋ 一件带墨线勾边的"东西"**——**不套武学图标那块压暗圆底**。圆底配上气环、45° 轴
才读成"武学"那一套，装备套上会和武学行打架。

15 §4.3 的「同一类别内构图取齐」在这批里落成两条：**武器 9 张斜 45°**（与招式同一根轴）、
**其余 18 张正面居中**（衣／甲／裤／护肩／腰带／戒指／佩饰）。

颜色**按材料走**（铁／青锋／锈／乌木／白蜡杆／皮／布／铜／玉／金），不按稀有度——
**稀有度不画进图标**（同 15 §4.3「星阶不画进图标」）：层级由列表 UI 的文字与颜色承担。
所以 `锈月`／`前代寨主遗物`／`淬毒指环` 的区别来自**造型与材料**（锈迹／鎏金／毒光），
不是"边框更花"。

一条踩过的：**剑的护手与柄一开始画粗了**（6×3 ＋ 3×5，比 3 px 宽的剑身还壮），
整体读成"一把刷子"。收成 5×2 ＋ 3×4 之后剑身才是主角——**32×32 上谁比谁粗就是谁当主角**。

### 招式 35 张：两条画法上的教训

**一、残影不能是"整把兵器的半透明副本"。** 第一版把本体按 `(-4, +4)` 再画一遍当残影，
结果**剑柄那一头一错就伸出底板圆外**，在图标边上留下一块暗疙瘩——读起来是"旁边掉了块东西"，
不是"这一下挥出去了"。第二版改成**三道与轴平行的短痕**（长度 8／6／4、垂直错开 2～4 px，
贴着刃走），只借用**轴的走向**、不借用兵器的形状，所以剑／刀／枪／掌五支剪影都能共用同一段代码。
另外立了一条断言：`assertInsidePlate()` 发现**落在底板圆外的像素就当场报错并点名**——
**落在圆外的东西在游戏里没有底板托着**（面板底色会直接透出来）。断言而不是"出图后再剪一刀"：
剪是静默的，等于把越界藏起来。（65 张现在都刚好收在圆内，最靠边的一笔连勾边离边还有 1 px。）

**二、星阶只改明度，不改形状。** `starLight()` 把 ★1→★5 从学派 `main` 提到提亮过的 `light`；
轮廓、角度、残影长度**一张都不许动**——同门排一行时，读起来要像"越练越亮"，不是"越练越花"。

**命名与验收**（不用记，跑一遍就知道）：

```bat
node tools\artgen\artgen.js               rem 出图
cmd /c tools\run_tests.bat                rem 硬门限：每张图的名字都必须是 skill_base 里的 id
cmd /c tools\run_windowed_smoke.bat       rem 真窗口：角色面板的武学行「有图才摆」，这一趟能看见
```

`_check_icon_file_names`（`tests/test_map_assets.gd`）会把「名字对不上表」的图当场点出来——
这是 2026-10-04 真实抓过 5 张的那条门限。**只要文件名 = `skill_id`，父目录是 `assets/icons/skill/`。**

**按类别分两批交的**（30 内功一次、35 招式一次），每批都单独跑绿、单独上线——
这也是 15 §六「可以分批交付」那条的用法。**下一批是装备 27**（紧接着做，中间不插别的批次：
武学图标与装备图标在角色页／行囊**同框出现**，分两批会让面板一半有图一半没图）。

### 地图道具：`props.js` 里的两张「剧情道具」

这两张不是运行期道具，是**地图资产**，所以路径常量该落在生成器侧（`tools/mapgen/map_kit.gd`），
不是 `chest.gd` / `trigger_point.gd` 那种运行期目录常量——**这条分界是小程序 2026-10-04 澄清的**。

| 文件 | 尺寸 | 谁摆 |
|---|---|---|
| `prop_ferry_pile.png` 封渡木桩 | 32×32 | 地编（`build_local_maps.gd::_build_ferry()`，已接） |
| `prop_luoyanpo_jiuche.png` 旧镖车 | **64×64** | 地编（换掉 `build_overworld.gd::_paint_old_cart()` 那 4 格） |

**旧镖车那条尺寸是硬约束**：原来它是四格瓦片拼的（2×2 格），缩成一张图就是这个量级——
多一格少一格都会让车与旁边三个观察点、林铁山那个 NPC 位点错位。画面按设计那句
「翻倒的车厢 ＋ 散落的镖货 ＋ 断掉的车辕 ＋ 只剩一个字的镖旗」出；
**木料一律朽木的灰褐**（用新木头的暖黄，这辆车看起来就像刚停下、不像搁了十年）。

### 头像只有一处定义：`actors.js`

这里曾经有一份 `avatars.js`，画着 9 张 NPC 头像里的前 7 张（更早的简版）。
入口是**先写 `actors.js`、后写 `avatars.js`**，于是那 7 张被**静默覆盖成简版**，
而只有 `actors.js` 里有的沈雁回留在**另一套画风**上——同一排头像两种画风，
代码里怎么读都读不出来。**2026-10-04 已删掉 `avatars.js`**：头像、敌人剪影都只有
`actors.js` 一处定义，9 张现在同一套（底框／肩与交领／头／眉眼／发式与胡须）。

**要加一个新 NPC 的头像**：在 `actors.js` 里写一个 `npcXxx()`（照 `npcShenYanhui()`
那个形状：`frame()` → `shoulders()` → `head()` → 再补这个人独有的东西），
然后把 `sprites/avatars/avatar_<npc_id>.png` 加进 `buildAll()`。
**文件名 = `npc_def.npc_id`，一位不能差**；`npc_def` 加行之后才会真有面板显示它。
